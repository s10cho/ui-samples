## 1. 사용자와 할 일

| 항목 | 내용 | 확인 / 가정 |
|---|---|---|
| 사용자 | 회의실·스튜디오를 빌리려는 사람(공간 운영사의 손님). 예약 화면을 처음 쓰거나 가끔 쓴다 | 가정 — 작업 지시("가상의 공간 예약") |
| 주요 작업 | ① 공간·날짜·시작 시간·이용 시간·인원을 고른다 ② 예약자 정보를 적는다 ③ 확인하고 예약을 확정한다 | 확인 — 작업 지시 |
| 빈도 | 한 사람이 한 달에 몇 번. 하루에 여러 번 반복하는 업무가 아니다 | 가정 |
| 들어오는 길 | 샘플 목록 페이지, 공간 소개 페이지의 "예약하기"(이 샘플에는 없음) | 가정 |
| 나가는 길 | 4단계 완료 화면에서 "새 예약 시작하기", 머리줄 "UI 샘플" 링크 | 가정 |

- 위저드를 고른 이유: 드물게 하는 작업이고(`PAT-ARC-05`·`PRN-B2B-08` 의 금지 대상이 아니다), 1단계의 고르는 값이 2·3단계보다 앞서 정해져야 한다(공간 → 빈 날 → 빈 시간). 작업 지시도 여러 단계를 요구한다.

## 2. 정보 우선순위

| 순위 | 정보·행동 | 이 순위인 이유 |
|---|---|---|
| 1 | 지금 단계와 남은 단계(단계 표시) | 위저드는 시작 전에 단계 수를 알리고 지금·끝난 단계를 보여야 한다(`PAT-FORM-12`) |
| 2 | 고를 수 있는 날과 시간, 고를 수 없는 이유(지난 날·마감) | 예약의 성패가 여기서 갈린다. 이유가 없으면 사용자는 고장으로 읽는다 |
| 3 | 지금까지 고른 내용과 요금(1·2단계 옆 요약) | 단계 사이를 오가지 않고도 고른 값을 확인한다 |
| 4 | 입력 오류와 고치는 법 | 칸 바로 아래에 둔다(`PAT-FORM-05`) |
| 5 | 확정 전 전체 요약과 항목별 "바꾸기" | 같은 값을 다시 입력하지 않고 고친다(`PAT-FORM-10`) |
| 6 | 완료 후 예약 번호 | 문의·변경에 쓰는 유일한 열쇠다 |

- 주 행동: 단계마다 하나 — "예약자 정보 입력하기" → "예약 내용 확인하기" → "예약 확정하기". 4단계는 "새 예약 시작하기".

- 옆 메뉴는 두지 않는다. 예약 흐름은 한 가지 일만 하는 화면이고, 이 샘플에 옮겨 갈 다른 메뉴가 없다. 없는 메뉴를 가짜 링크로 채우지 않는다.

### 단계별 본문

| 단계 | 주소 | 본문 |
|---|---|---|
| 1 공간·시간 | `?step=1`(기본) | 공간(4곳, 라디오 타일) → 날짜(달력) · 이용 시간(묶음 버튼 1~4시간) · 시작 시간(라디오 타일) → 인원(빼기·더하기 버튼 + 숫자 입력) |
| 2 예약자 정보 | `?step=2` | 이름 · 휴대전화 · 이메일(필수) · 요청 사항(선택, 200자) |
| 3 확인 | `?step=3` | 예약 내용(공간·날짜·시간·인원·요금) · 예약자(이름·휴대전화·이메일·요청 사항) — 줄마다 "바꾸기", 취소 규정과 동의 체크 |
| 4 완료 | `?step=4` | 완료 제목, 예약 번호와 복사 버튼, 요약, 일정에 넣는 법(안내 글만) |

- 이용 시간을 시작 시간보다 앞에 둔다. 시작 시간 목록은 "그 시간부터 이용 시간만큼 이어서 빈 시간"만 고를 수 있어서, 이용 시간이 먼저 정해져야 목록이 정확하다.

- 라디오 타일: kit 의 `ds-check` 는 줄글 라디오라 공간 이름·정원·요금을 한 칸에 담기 어렵고, `ds-segmented` 는 2~7개용이다(시작 시간은 최대 12개). 그래서 진짜 `<input type="radio">` 를 타일 전체에 깔고(누르는 영역 = 타일) 체크 아이콘 + 테두리 + 굵기로 고른 상태를 보인다. 화살표 키 이동은 브라우저 라디오 묶음이 한다.
- 달력: kit 에 날짜 고르기가 없다. `<table>`(요일 열 머리) 안의 `<button>` 으로 만들고, 한 번에 한 칸만 Tab 순서에 둔다(roving tabindex). 고른 날 `aria-pressed="true"`, 오늘 `aria-current="date"`, 고를 수 없는 날 `aria-disabled="true"` + 툴팁에 이유. 버튼 이름은 `aria-label` 대신 화면에 숨긴 글로 만든다("11월 [20]일 금요일, 예약이 다 찼어요") — 보이는 숫자가 이름 안에 낱말로 남아야 한다(WCAG 2.5.3, axe `label-content-name-mismatch`).
- 새 토큰(샘플 CSS 맨 위 `:root`, kit 에 같은 뜻의 토큰이 없다): `--booking-flow-summary-w` 18rem(고른 내용 열) · `--booking-flow-cal-max` 24rem(달력 최대 너비) · `--booking-flow-col-min` 18rem(달력·시간 2열로 나누는 최소 열 너비) · `--booking-flow-space-min` 10rem(공간 타일, 375 폭에서 2열) · `--booking-flow-slot-min` 5.5rem(시간 타일) · `--booking-flow-people-w` 5rem(인원 숫자 칸) · `--booking-flow-sum-key` 4rem(고른 내용 이름 칸). 달력 칸 높이는 kit `--ds-control-height-lg`(40)·`--ds-target-min`(터치 44) 중 큰 값이다. 표 행이 아니라서 `--ds-row-height`(터치 56)를 쓰지 않는다. 샘플 CSS 에 색·너비 전환(transition)을 두지 않는다(kit 1회차 변경 6, `MOT-05`).
