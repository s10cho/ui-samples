- 가로 휴대폰(높이 480 미만, 가로가 더 김): 그림은 왼쪽 60% 를 높이 전체로 채운다. 오른쪽 40% 에 목록과 상세를 두고 그 열만 스크롤한다.
- 넓은 폭에서 휠은 확대에 쓴다(페이지가 스크롤되지 않는다). 좁은·중간 폭에서는 휠을 페이지 스크롤에 두고, 확대는 버튼과 두 손가락 집기로만 한다. 조작 안내도 이 조건으로 고른다(6절).
- 그림 위에 얹는 글자는 모두 불투명 표면 위에 둔다. 움직이는 그림 위 글자는 대비가 계속 바뀌기 때문이다. 밤에도 UI 는 흰 표면이다.
- 3D 판의 "진행 문구" 영역은 없앴다. 그림이 HTML 안에 있어 기다릴 것이 없다(5절 초기 로딩).
- 안내 배너 영역(`aria-live`)은 스크립트가 돌 때도 늘 렌더링한다. 비어 있을 때는 화면에서만 숨긴다(`display: none` 을 쓰지 않는다). 그래야 시작하다 실패해 배너를 넣을 때 화면낭독기가 알린다.

### 3-1. 그림 구성

모양은 3D 판과 같은 저폴리(면이 보이는 단순한 입체)와 납작한 음영이다. 그림 파일·텍스처 없이 모두 코드로 만든다. 건물 자리·크기·높이·벽 색·지붕 색과 나무 크기는 3D 판과 같은 좌표와 같은 씨앗 난수(같은 순서로 뽑는다)로 계산한다. 그래서 두 판의 배치가 같다.

| 항목 | 정한 것 |
|---|---|
| 보는 방향 | 남동쪽 위에서 내려본다(2:1 아이소메트릭, 내려보는 각 30°). 3D 판의 처음 시점(남동쪽, 35°)과 같은 쪽이다. 화면에서 공원 분수가 앞(아래), 전망 타워가 뒤(위), 시계탑 기차역이 왼쪽, 시장 골목이 오른쪽에 보인다 |
| 그리는 범위 — 모형 판 | 3D 판의 블록(명소가 있는 곳, 동서 ±15.5 · 남북 −16.5~17.5)을 네모난 판 하나로 잘라 그린다. 판의 앞면(남쪽)과 오른쪽 면(동쪽)이 보이고, 강이 판을 가로질러 오른쪽 면에 물길 자국을 남긴다. 판 밖은 하늘색 바탕이다. 3D 판에서 안개 속으로 이어지던 블록 밖 건물은 그리지 않는다 |
| 면 밝기 | 해 방향은 3D 판의 해 자리(서남서)와 같고, 높이만 올려 윗면이 가장 밝게 읽히게 했다. 면마다 방향을 계산해 4단계(윗면 · 햇빛 쪽 · 비스듬한 면 · 그늘 면) 중 하나로 칠한다. 상자 건물은 윗면 · 남쪽 면(햇빛 쪽) · 동쪽 면(그늘 면)이 보인다. 보이지 않는 면은 그리지 않는다 |
| 그리는 순서 | 판 옆면 → 물(강물·물결·물에 비친 불빛) → 북쪽 둑 벽 → 땅(보도·길·풀밭·기찻길·가로등 아래 빛) → 강 북쪽 물체 → 배 → 아치 다리(다리 위 차 포함) → 강 남쪽 물체. 물체끼리는 땅 위 자리(동서·남북 범위)로 앞뒤를 정한다 |
| 창문 | 건물 면마다 창문 구역 하나를 SVG 무늬(pattern)로 칠한다. 층 높이·창 간격·창 크기·층 수·열 수는 3D 판과 같다. 어느 창에 불이 켜지는지는 무늬 안에서 정하고(3D 판과 같은 비율), 건물마다 무늬의 시작 칸을 다르게 해 같은 배치가 되풀이되지 않게 한다 |

### 3-2. 보는 범위(시점)

3D 판의 카메라 대신 SVG 의 `viewBox`(그림에서 화면에 보일 범위)를 바꾼다. 그림을 다시 그리지 않고 보이는 범위만 옮긴다.

| 항목 | 값 |
|---|---|
| 처음 시점 | 모형 판과 명소 표지 자리 전체가 보이는 자리의 84% 를 채운다(가로·세로 중 빡빡한 쪽 기준). 보이는 자리 = 넓은 폭에서는 정보 패널이 가린 만큼 뺀 폭 × (위쪽 토글 아래 + 표지 알약 한 줄 높이)부터 아래쪽 조작 버튼 위까지의 높이. 그 가운데에 둔다. 가장 높은 명소(전망 타워)의 표지가 토글 아래로 들어가지 않게 하려는 것이다(3D 판 검수 지적 2). 글자를 키워 남는 높이가 40% 아래면 전체 높이를 쓴다 |
| 배율 제한 | 처음 배율의 0.56배(멀리 보기 2번) ~ 5.62배(가까이 보기 6번). 버튼 한 번에 4/3 배. 도시는 섬보다 물체가 작아서 island-park-iso(4번)보다 두 번 더 가까이 간다 |
| 가운데 제한 | 보이는 범위의 가운데는 그림 범위 안에서만 움직인다. 도시가 화면 밖으로 사라지지 않는다 |
| 명소를 고르면 | 그 명소 그림과 표지가 보이는 자리 높이·폭의 50% 를 채우도록 확대·이동한다(600ms, 감속 곡선). 처음 배율보다 작아지지 않는다 |
| 기울기·회전 | 해당 없음 — 2D 그림은 보는 방향이 하나로 고정된다(island-park-iso 설계서 3-2절과 같은 이유) |
| 자동 회전 | 해당 없음 — 돌릴 시점이 없다 |
| 인트로 | 없음. 첫 화면부터 처음 시점이다 |

- 3D 판의 "돌리기" 버튼 2개 자리에 끌기의 버튼 대안인 옮기기 버튼 4개를 둔다(`A11Y-WCAG-07`). 이름은 "~ 보기" 꼴이고, 한 번에 보이는 폭(높이)의 1/4 만큼 400ms 에 옮긴다. island-park-iso 와 같다.

### 4-2. 기술 선택과 예산

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 그리기 | 인라인 SVG. `tools/build-scene.mjs`(Node, 의존성 없음)가 3D 판과 같은 좌표·씨앗 난수로 면을 계산해 `index.html` 의 표시 사이에 넣는다 | 그림이 HTML 과 함께 도착한다. 스크립트가 실패해도 그림이 보인다 |
| 스크립트 | 일반 스크립트 3개: `js/iso2d.js`(공용 뼈대 `shared/iso2d` — 면 계산·화면 틀) · `js/iso-geom.js`(좌표 계산, 빌드와 같이 씀) · `js/scene.js`(문구·설정·움직임). ES 모듈·importmap·묶음 파일 없음 | 서버와 파일(`file://`) 두 방식에서 같은 코드가 돈다 |

| 바닥에 눕는 것 | 땅·길·풀밭·물·가로등 아래 빛·기찻길 침목은 바닥 좌표 그대로 적고 묶음 하나의 `transform` 으로 눕힌다. 원은 `<circle>`, 네모는 `<rect>` 로 짧게 쓴다 | 점마다 투영하지 않아 전송량이 준다 |
| 창문 | 건물 면마다 창문 구역 하나(면 좌표 `transform` + SVG 무늬). 무늬 3종: 강 북쪽 건물, 강 남쪽 건물(빈 칸 포함), 명소 건물(밤에 모두 켜짐) | 창문 수천 개를 하나씩 그리면 요소 수와 전송량이 예산을 넘는다 |
| 움직이는 부분 | 차 8대(몸체·유리 상자 면 6개 + 앞뒤 불빛 2개 + 투명도), 배(이동 `transform`·투명도), 물결(이동 `transform`), 분수 물줄기(면 1개 + 우산 이동 1개), 타워 꼭대기 불빛(투명도). 매 프레임 이것만 바꾼다(70개 안팎) | 그림 전체를 다시 그리지 않는다 |

## 6. 상호작용

| 동작 | 마우스·터치 | 키보드 | 결과 |
|---|---|---|---|
| 명소 고르기 | 그림의 표지, 목록 행이나 칩을 클릭·탭 | 목록에서 Tab 으로 옮겨 Enter·Space | 그 명소로 600ms 에 확대·이동(감속 곡선). 상세가 바뀐다. 목록·표지에 선택 표시. 상태 알림 |
| 처음 시점으로 | "처음 시점으로 돌아가기" 버튼 | Esc, 또는 버튼. 조작 버튼 툴팁이 보이고 있으면 첫 Esc 는 툴팁만 닫는다 | 처음 시점으로 돌아간다. 선택을 푼다. 상세는 미선택 상태 |
| 조작 버튼 툴팁 | 마우스를 올리면 보인다. 툴팁 위로 포인터를 옮겨도 닫히지 않는다 | 포커스를 받으면 보인다. Esc 로 닫는다 | WCAG 1.4.13 |
| 도시 옮기기 | 마우스 끌기(모든 방향, 모든 폭). 터치: 한 손가락 가로 끌기, 두 손가락 끌기 | "왼쪽 보기 · 위쪽 보기 · 아래쪽 보기 · 오른쪽 보기" 버튼(보이는 폭·높이의 1/4) | 가운데 제한 안에서 옮겨진다. 선택은 그대로 둔다 |
| 도시 돌리기 · 기울이기 | 해당 없음 — 2D 그림은 보는 방향이 고정이다(3-2절) | 해당 없음 | — |
| 가까이·멀리 | 넓은 폭: 휠·트랙패드 집기(포인터 자리를 기준으로). 터치: 두 손가락 벌리기·오므리기. 좁은·중간 폭의 마우스: 버튼 | "가까이 보기"·"멀리 보기" 버튼(가운데 기준) | 배율 제한 안에서 움직인다 |

| 밤으로·해 질 녘으로 바꾸기 | 토글 버튼 | Tab + Enter·Space | 색이 600ms 에 바뀐다(움직임 줄이기·멈춤이면 즉시). 라벨이 다음 행동으로 바뀐다. 포커스는 버튼에 그대로 있다 |
| 3D로 보기 | 링크 클릭·탭 | Tab + Enter | 3D 판으로 이동한다 |
| 이동 중 다른 입력 | 확대·이동 중에 끌기·휠·두 손가락 | 이동 중에 다른 버튼 | 진행 중인 이동을 바로 취소하고 새 입력을 따른다 |

- 조작 안내는 입력 방법과 폭에 맞춰 세 가지 중 하나만 보인다(island-park-iso 검수 "고치면 좋은 것" 3). 넓은 폭 + 마우스: 휠 안내. 좁은·중간 폭 + 마우스: 휠이 확대하지 않으므로 버튼 안내. 터치: 두 손가락 안내. 휠 확대 조건(`min-width: 1024px`)과 휠 안내 조건이 같은 값이다.
- 고르는 법 안내는 모든 모드에서 보인다. 스크립트가 돌 때는 "명소를 고르면 그곳으로 가까이 가요", 스크립트가 없을 때는 "명소 이름을 누르면 그 설명으로 가요"(3D 판 검수 지적 4).
- 포커스 순서: 건너뛰기 링크 → 3D로 보기 → 움직임 토글 → 시간대 토글 → 조작 버튼 7개 → 명소 목록 → 상세 안 요소(있으면). 좁은 폭의 화면 순서(상단 바 → 그림 → 목록)와 같다.
- 단축키: Esc 만 둔다. 보이는 툴팁이 있으면 툴팁을 닫고, 없으면 처음 시점으로 간다. 글자 한 개 단축키는 두지 않는다.
- 표지는 `aria-hidden="true"`, `tabindex="-1"` 로 둔다. 키보드와 화면낭독기는 목록으로 같은 일을 한다.
- 그림 `<svg>` 에는 `role="img"` 와 7절의 대체 텍스트를 단다. 그림 안의 면은 화면낭독기가 읽지 않는다. 같은 그림을 가리키는 이름은 이것 하나다(3D 판 검수 지적 7 — 이 판에는 캔버스와 포스터가 겹치지 않는다).

## 10. 설계 메모 — 흔한 기본값과 비교

| 처음 안 | 흔한 기본값과 같은 점 | 바꾼 것 |
|---|---|---|
| 도시를 화면 끝까지 채우고 가장자리를 안개 그라데이션으로 흐리게 | 끝없는 도시 일러스트의 흔한 처리다. 그라데이션 장식에 가깝다(`SLOP-03`) | 블록을 네모난 모형 판으로 자르고 판 옆면을 보인다. 바탕은 하늘색 단색 |
| 어두운 UI + 보라·청록 네온 야경 | 야경 화면의 가장 흔한 모양이다(`SLOP-01`) | UI 는 밤에도 흰 표면. 불빛은 따뜻한 노란색 하나 |
| 창문을 하나씩 사각형으로 그리기 | 가장 쉬운 방법이다. 창문이 수천 개라 요소 수가 예산의 몇 배가 된다 | 면마다 창문 구역 하나를 무늬로 칠한다. 층·열 간격은 3D 판과 같다 |
| 밤 불빛에 방사형 그라데이션 후광 | AI 기본 장식으로 꼽히는 빛 번짐이다(`SLOP-03`) | 땅에는 노란 원 두 겹을 낮은 투명도로 겹치고, 물에는 짧은 노란 선을 둔다 |
| 3D 판의 "돌리기" 버튼을 그대로 두고 그림을 좌우 반전 | 버튼 수를 맞추려는 흔한 타협이다. 반전하면 동서가 바뀌어 위치 한 마디("서쪽 강가")와 어긋난다 | 돌리기를 없애고 옮기기 4개를 둔다(island-park-iso 결정) |
| 명소마다 아이콘 타일이 붙은 카드 격자 | `SLOP-06`·`SLOP-07` 이 지목한 카드 키트다 | 3D 판과 같은 목록 행. 좁은 폭은 칩 |

- `MOT-01` 예외(3D 판과 같다): 명소로 확대·이동은 600ms 로 한다. 큰 이동을 400ms 에 끝내면 오히려 어지럽다(추정). 대신 감속 곡선을 쓰고(`MOT-04`), 입력이 오면 바로 취소하고(`MOT-10`), OS 움직임 줄이기가 켜지면 즉시 전환한다(`MOT-06`).
- `MOT-05` 예외: 시간대 전환에서 그림 면의 `fill`·`stroke` 색을 600ms 에 바꾼다. 3D 판이 빛과 색을 600ms 에 바꾸는 것과 같은 일이다. UI 요소는 색을 애니메이션하지 않는다. 움직임 줄이기·멈춤이면 즉시 바꾼다.
- 위키 공백: 위키의 화면 유형 표에는 소비자용 첫 화면·그림 탐색 화면 유형이 없다. 목록 + 상세로 옮겨 적었다.
