## 1. 사용자와 할 일

| 항목 | 내용 | 확인 / 가정 |
|---|---|---|
| 사용자 | 이 도시에 관심이 있는 일반 방문자 | 가정 — 요청에 사용자 설명이 없다 |
| 주요 작업 | ① 강을 낀 도시 한 블록의 전체 모습을 본다 ② 명소 하나를 골라 위치와 설명을 본다 ③ 해 질 녘과 밤의 분위기를 바꿔 본다 | 요청("강을 낀 가상의 작은 도시 한 블록을 3D로 보여 주는 첫 화면", "해 질 녘 ↔ 밤")에서 정함 |
| 빈도 | 방문 한 번에 몇 분, 명소 2~5곳을 본다 | 가정 |
| 기기 | 휴대폰 방문이 많다. 그래서 성능 예산은 휴대폰 기준으로 잡는다 | 가정 |
| 들어오는 길 | 샘플 목록 페이지의 링크로 들어온다 | 가정 |
| 나가는 길 | 없음 — 첫 화면 한 장이고 바깥 링크를 두지 않는다 | 열린 질문 5번 기본안 |

## 2. 정보 우선순위

| 순위 | 정보·행동 | 이 순위인 이유 |
|---|---|---|
| 1 | 강을 사이에 둔 작은 도시의 전체 모습(3D 장면) | 방문자의 첫 판단은 "여기는 어떤 곳인가"다. 장면이 그 답이다 |
| 2 | 명소 5곳의 이름과 도시 안 위치 | 장면을 본 다음 "무엇이 있나"를 찾는다. 표지와 목록이 같은 정보를 준다 |

| 5 | 둘러보는 방법(끌기·확대·버튼) | 처음 한 번 필요하다. 강제 튜토리얼 대신 맥락 안내로 준다 |
| 6 | 움직임 멈추기 | 대부분은 안 쓰지만, 어지럼을 느끼는 사람에게는 꼭 필요하다. 항상 같은 자리에 둔다 |

- 주 행동(primary action): 명소 고르기.

- 가로 휴대폰(높이 480 미만, 가로가 더 김): 장면은 왼쪽 60% 를 높이 전체로 채운다. 오른쪽 40% 에 목록과 상세를 두고 그 열만 스크롤한다.
- 넓은 폭에서 휠은 확대에 쓴다(페이지가 스크롤되지 않는다). 좁은·중간 폭에서는 휠을 페이지 스크롤에 두고, 확대는 버튼과 두 손가락 집기로만 한다.
- 장면 위에 얹는 글자는 모두 불투명 표면 위에 둔다. 움직이는 장면 위 글자는 프레임마다 대비가 바뀌기 때문이다. 밤에도 UI 는 흰 표면이다.

### 3-1. 장면 구성

모양은 저폴리(면이 보이는 단순한 입체)와 납작한 음영으로 만든다. 장난감 모형처럼 보이게 한다. 모델·텍스처 파일은 쓰지 않고 모두 코드로 만든다. 실제 도시·건물·다리를 본뜨지 않는다. 가상의 도시다.

좌표: x 는 동쪽, z 는 남쪽이 +. 강은 서쪽에서 동쪽으로 조금 굽이치며 블록 가운데를 지난다. 강 남쪽이 옛 시가지(낮은 건물), 북쪽이 새 시가지(높은 건물)다.

| 요소 | 도시 안 위치 | 움직임 | 표지 |
|---|---|---|---|
| 강 | 블록 가운데를 서→동으로 지나 안개 속으로 이어진다. 폭 약 5. 양쪽은 돌 둑 | 낮은 물결, 주기 약 4초 | 없음 |
| 땅과 길 | 강 양쪽. 강변 산책로·강변 도로, 다리에서 남북으로 뻗는 큰길, 남쪽 동서 도로 | 없음 | 없음 |
| 하늘 | 단색 + 같은 색 안개. 지평선이 하늘에 녹아든다 | 없음 | 없음 |
| 전망 타워 | 강 북쪽 언덕 위. 도시에서 가장 높다. 처음 시점의 시선 끝 | 꼭대기 불빛이 2.4초 주기로 천천히 밝아졌다 어두워진다(번쩍이지 않는다) | 전망 타워 |
| 아치 다리 | 블록 한가운데에서 강을 남북으로 건넌다 | 차 불빛이 양쪽 차로로 오간다 | 아치 다리 |
| 시계탑 기차역 | 강 남쪽 서쪽. 기찻길이 서쪽 안개 속으로 이어지는 끝 역. 역 동쪽 끝에 시계탑, 승강장에 기차 한 편성이 서 있다 | 없음. 시계 바늘은 해 질 녘 6시 반, 밤 9시를 가리킨다 | 시계탑 기차역 |
| 시장 골목 | 강 남쪽 동쪽. 동서로 난 좁은 골목 양쪽에 낮은 가게와 차양 | 없음. 밤에 골목 위 전구 줄이 켜진다 | 시장 골목 |
| 공원 분수 | 블록 남쪽 공원 한가운데. 처음 시점의 앞쪽 | 물줄기가 오르내린다(주기 약 3초) | 공원 분수 |
| 건물 | 명소 사이 블록을 채운다. 블록 밖으로는 낮은 건물이 안개 속까지 이어진다 | 없음 | 없음 |
| 창문 | 건물 네 면 | 없음. 밤에 켜진다(3-1절 아래 표) | 없음 |
| 가로등·나무 | 강변 산책로, 큰길, 공원 | 없음 | 없음 |
| 배 | 강 위 | 서→동으로 천천히 지나간다. 한 바퀴 약 45초 | 없음 |

해 질 녘과 밤은 같은 장면에 빛과 색만 바꾼다. 모양과 명소 위치는 같다.

| 항목 | 해 질 녘(기본) | 밤 |
|---|---|---|
| 하늘·안개 | 옅은 살구색 단색 | 짙은 남색 단색 |
| 주 빛 | 서쪽 낮은 해(주황빛, 그림자가 길다) + 하늘빛 | 달빛(푸른 흰색, 약하게) + 하늘빛 |
| 창문 | 대부분 어두운 유리. 약 1할만 먼저 불이 켜져 있다 | 약 6할에 따뜻한 노란 불이 켜진다. 나머지는 어둡다 |
| 가로등 | 꺼짐 | 켜짐. 가로등 아래 땅에 둥근 빛이 번진다(따로 빛을 계산하지 않고 반투명 원판으로 그린다) |
| 아치 다리 | 흰 아치 | 아치를 따라 전구가 켜진다 |
| 시장 골목 | 차양 | 골목 위 전구 줄이 켜진다 |
| 전망 타워 | 꼭대기 불빛이 약하게 보인다 | 꼭대기 불빛과 전망대 둘레 전구가 켜진다 |
| 차 | 차 모양만 | 앞 불빛(따뜻한 흰색)·뒤 불빛(붉은색)이 켜진다 |
| 강 | 하늘빛을 받은 회청색 물결 | 짙은 물결. 다리·시장 골목·기차역 가까운 물이 불빛으로 따뜻하게 밝아진다(따로 그리는 면 없이 물결 색을 데운다) |
| 표지·패널 | 흰 표면 | 흰 표면 그대로(UI 는 다크 모드가 아니다) |

- 들어올 때는 늘 해 질 녘으로 시작한다. 고른 시간대를 저장하지 않는다(열린 질문 1번).
- 시간대 전환은 빛과 색을 600ms 에 바꾼다(감속 곡선). OS 움직임 줄이기가 켜져 있거나 움직임 멈춤이면 즉시 바꾼다.

### 3-2. 시점(카메라)

| 항목 | 값 |
|---|---|
| 처음 시점 | 남동쪽 위에서 비스듬히 내려본다(내려보는 각 약 35°). 블록 전체가 장면 폭의 60~70% 를 채운다. 공원 분수가 앞, 전망 타워가 뒤 |
| 각도 제한 | 내려보는 각 15°~70°. 땅 밑이 보이지 않게 한다 |
| 거리 제한 | 가장 가까이: 명소 하나가 장면 높이의 절반. 가장 멀리: 블록이 장면 폭의 40% |
| 중심점 제한 | 사용자가 중심점을 옮기는 조작이 없다. 중심점은 처음 시점과 명소 시점 사이에서만 움직인다 |
| 명소를 고르면 | 중심점을 그 명소로, 거리를 명소 크기에 맞춰 옮긴다. 세로로 긴 장면(가로÷세로 1.25 미만)에서는 최대 2배까지 멀리서 본다. 전망 타워는 높이가 있어 더 멀리서, 아치 다리는 강을 따라 비스듬히 본다 |
| 자동 회전 | 처음 들어왔을 때만 아주 느리게(한 바퀴 약 90초). 사용자가 한 번 조작하면 끄고 다시 켜지 않는다 |
| 인트로 | 없음. 첫 프레임부터 처음 시점이다 |
| 첫 프레임의 장면 시각 | 포스터를 찍은 장면 시각과 같은 값에서 시작한다. 포스터가 3D로 바뀔 때 차·배·분수 위치가 튀지 않는다(첫 샘플 검수 "고치면 좋은 것" 2번) |

### 4-2. 기술 선택과 예산

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 3D 라이브러리 | Three.js 0.187.0(MIT). 앱 코드가 쓰는 클래스만 한 파일로 묶어 `vendor/three/` 에 둔다(`tools/build-three.mjs`) | 첫 샘플과 같다. CDN 장애와 외부 요청을 없앤다 |

| 명소 고르기 | 장면의 표지, 목록 행이나 칩을 클릭·탭 | 목록에서 Tab 으로 옮겨 Enter·Space | 시점이 명소로 600ms 에 이동(감속 곡선). 상세가 바뀐다. 목록·표지에 선택 표시. 상태 알림 |

| 가까이·멀리 | 넓은 폭: 휠·트랙패드 집기. 터치: 두 손가락 벌리기·오므리기. 좁은·중간 폭의 마우스: 버튼 | "가까이 보기"·"멀리 보기" 버튼 | 거리 제한 안에서 움직인다 |

| 이동 중 다른 입력 | 시점 이동 중에 끌기·휠·탭 | 이동 중에 다른 버튼 | 진행 중인 이동을 바로 취소하고 새 입력을 따른다 |

- 조작 안내는 입력 방법에 맞춰 세 가지 중 하나만 보인다(첫 샘플 검수 "고치면 좋은 것" 1번). 넓은 폭 + 마우스: 휠 안내. 좁은·중간 폭 + 마우스: 휠이 확대하지 않으므로 버튼 안내. 터치: 두 손가락 안내.
- 포커스 순서: 건너뛰기 링크 → 움직임 토글 → 시간대 토글 → 시점 조작 버튼 5개 → 명소 목록 → 상세 안 요소(있으면). 좁은 폭의 화면 순서(장면 → 목록)와 같다.
- 단축키: Esc 만 둔다. 보이는 툴팁이 있으면 툴팁을 닫고, 없으면 처음 시점으로 간다. 글자 한 개 단축키는 두지 않는다.
- 표지는 `aria-hidden="true"`, `tabindex="-1"` 로 둔다. 키보드와 화면낭독기는 목록으로 같은 일을 한다.
- 장면 `<canvas>` 에는 `role="img"` 와 7절의 대체 텍스트를 단다. 3D가 보이지 않는 loading·lost·fallback 에서는 캔버스에 `aria-hidden="true"` 를 주고, ready 에서는 포스터 쪽에 준다. 같은 이름의 그림이 접근성 트리에 두 번 나오지 않는다.
- 배너를 지우거나 바꿀 때 포커스가 배너 안에 있었으면, 장면 토글 가운데 보이는 첫 버튼으로 옮긴다. 보이는 토글이 없으면 명소 목록 머리(`#landmarks`, `tabindex="-1"`)로 옮긴다. 포커스가 body 로 떨어지지 않는다(`moveFocusAfterBanner()`).
- live 영역(배너 자리 `aria-live`, 진행 문구 `role="status"`)은 비어 있어도 렌더링해 두고 화면에서만 숨긴다. `display:none` 을 쓰지 않는다.

| 명소마다 사진·아이콘이 붙은 카드 격자 | `SLOP-06`·`SLOP-07` 이 지목한 카드 키트다 | 이름 + 위치 한 마디의 목록 행. 좁은 폭은 칩 |
| 건물마다 따로 그린 상세 모델 | 그리기 호출과 삼각형이 예산을 넘는다 | 상자 하나 + 창문 면. `InstancedMesh` 로 종류마다 한 번에 그린다 |
| 3D 로딩 중 가운데 스피너 | 기다림을 보이는 흔한 방법이다(`STA-14`) | 처음 시점과 같은 구도의 포스터 이미지를 먼저 보인다. 3D가 실패해도 같은 이미지가 남는다 |

- `MOT-01` 예외: 시점 이동과 시간대 전환은 600ms 로 한다. 첫 샘플과 같은 이유다 — 큰 회전을 400ms 에 끝내면 너무 빨라 오히려 어지럽다(추정). 대신 감속 곡선을 쓰고(`MOT-04`), 입력이 오면 바로 취소하고(`MOT-10`), OS 움직임 줄이기가 켜지면 즉시 전환한다(`MOT-06`).
- 위키 공백: 이 위키의 화면 유형 표에는 소비자용 첫 화면·3D 화면 유형이 없다. 이 설계서는 목록 + 상세로 옮겨 적었다.

첫 샘플 검수(2026-11-17, 2회차)에서 남은 "고치면 좋은 것"을 이 설계에서 처리한 방법:

| 첫 샘플 지적 | 이 설계의 처리 | 적은 곳 |
|---|---|---|
| 1. 폭 1024 미만 마우스 기기에서 "휠로 가까이" 안내가 보이지만 휠은 확대하지 않는다 | 안내를 세 가지로 나눠, 휠 확대가 되는 조건(넓은 폭 + 마우스)에서만 휠 안내를 보인다 | 6절, 7절 |
| 2. 포스터→3D 교체 순간 움직이는 물체 위치가 다르다 | 3D 첫 프레임의 장면 시각을 포스터 촬영 시각과 같게 둔다 | 3-2절 |
| 3. 한 줄 배너의 문구와 닫기 버튼 세로 중심이 약 10px 어긋난다 | 닫기 버튼 중심을 문구 첫 줄 중심에 맞춘다 | 4절 배너 |
| 4. 그림자 패널 안 테두리 행이 카드 안 카드로 읽힌다(`SLOP-04` 반복) | 중간·넓은 폭 목록 행의 테두리를 없애고 옅은 바탕으로 바꾼다 | 4절 목록 행 |
