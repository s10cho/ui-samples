## 1. 사용자와 할 일

| 항목 | 내용 | 확인 / 가정 |
|---|---|---|
| 사용자 | 고객을 응대하는 영업·상담·운영팀 담당자 | 가정 — 작업 지시는 "고객 한 명의 상세를 보고 편집"만 정했다 |
| 주요 작업 | ① 연락처·주소·등급을 확인한다 ② 바뀐 연락처·메모를 고쳐 저장한다 ③ 최근 주문과 누가 무엇을 고쳤는지 확인한다 | 확인 — 작업 지시(보기 모드 4영역, 편집 모드, 저장 흐름) |
| 빈도 | 하루 여러 번 연다. 고치기는 그보다 드물다 | 가정 |
| 들어오는 길 | 고객 목록·상담 화면·주문 화면의 고객 이름 링크 | 가정 — 이 샘플에는 고객 목록이 없다 |
| 나가는 길 | 브라우저 뒤로, 옆 메뉴의 "샘플 목록" | 가정 |

## 2. 정보 우선순위

| 순위 | 정보·행동 | 이 순위인 이유 |
|---|---|---|
| 1 | 고객 이름과 등급 | 맞는 고객을 열었는지가 첫 판단이다 |
| 2 | 휴대 전화번호·이메일·주소 | 응대할 때 가장 자주 찾는 값이다. 형식만 보고 뜻을 아는 값이라 라벨을 뺀다(`PAT-DETAIL-02`) |
| 3 | "고객 정보 고치기" 버튼 | 이 화면의 유일한 주 행동이다 |
| 4 | 메모 | 응대할 때 알아 둘 약속·주의를 팀이 함께 본다 |
| 5 | 최근 주문 5건 | 문의가 주문과 이어지는 일이 많다 |
| 6 | 변경 기록 | 값이 언제·누구 때문에 바뀌었는지 확인할 때만 본다 |

- 주 행동: 보기 모드 "고객 정보 고치기", 편집 모드 "변경 내용 저장". 영역마다 강조 버튼은 하나다(`CMP-BTN-02`).

## 4. 컴포넌트

모두 kit(`shared/app`)의 기존 부품이다. 이 화면만 쓰는 배치(`ce-` 접두어)는 `customer-edit/css/page.css` 에 토큰으로만 만든다.

- 주문 묶음(section)에는 이름을 달지 않고, 가로 스크롤 틀(region)에만 "최근 주문" 이름을 단다. 같은 이름의 region 이 겹치지 않게 한다.
- 주문 번호·주문일 칸은 하이픈에서 끊기지 않게 `white-space: nowrap`(글자 200% 에서는 틀 안 가로 스크롤).
- 주문 표 틀은 kit 기본 `ds-table-wrap`(+ `role="region"`·`aria-labelledby`·`tabindex="0"`)을 쓴다. 5행뿐이라 높이를 제한하는 `--scroll` 이 필요 없다. 글자 200% 에서 열이 가로로 넘치므로 넘친 칸을 자르는 `--page` 도 쓰지 않는다. 넘치면 표 틀 안에서만 가로로 스크롤한다(`TYP-04`).
- 767 이하에서 쌓은 표의 빈 머리 띠·왼쪽 자리는 kit 2회차가 없앴다. 샘플의 임시 메움은 지웠다.
- 새로 만드는 부품은 없다. 오류 요약은 배너 부품의 모양을 그대로 쓰고 몸통에 링크 목록만 넣는다. 배너 부품(`DS.banner.show`)은 글만 받고 링크 목록을 받지 않아서 HTML 로 둔다.
- 샘플 토큰: `--customer-edit-side-min`(오른쪽 열 최소 폭 — kit 에 열 폭 토큰이 없어 `--ds-size-card-min` 의 별칭), `--customer-edit-skeleton-btn`(스켈레톤의 주 버튼 자리 너비 9rem — kit 에 버튼 너비 토큰이 없다), `--customer-edit-sk-size`·`--customer-edit-sk-leading`(스켈레톤 막대가 흉내 내는 글줄 크기·줄 높이, kit 토큰을 가리킨다).

## 6. 상호작용

| 동작 | 마우스·터치 | 키보드 | 결과 |
|---|---|---|---|
| 편집 시작 | "고객 정보 고치기" | Enter · Space | 폼이 보이고 "고객 이름" 칸으로 포커스. 주소에 `?mode=edit`(기록 하나 추가 — 뒤로 가기가 보기 모드로 간다) |
| 칸 검증 | 칸을 떠날 때 | Tab | 틀리면 칸 아래 오류. 오류가 있는 칸은 글자마다 다시 보고 맞는 순간 지운다. 우편번호 5자리·휴대 전화번호 11자리는 다 채운 순간 본다 |
| 전화번호 정리 | 칸을 떠날 때 | Tab | 맞는 번호면 하이픈을 넣어 `000-0000-0000` 꼴로 바꾼다. 받는 형식은 공백·하이픈·점 모두 |
| 저장 | "변경 내용 저장" | Enter(한 줄 칸 안), 버튼 Enter | 오류가 있으면 요약 + 첫 오류 칸 포커스. 바꾼 칸이 없으면 요청 없이 보기 모드로 돌아가고 live 로 알림. 그 밖에는 저장 중 → 보기 모드 + 성공 배너 |
| 오류 요약 링크 | 칸 이름 링크 | Enter | 그 칸으로 포커스 |
| 저장하지 않고 닫기 | 버튼 | Enter | 고친 칸이 없으면 바로 보기 모드("고객 정보 고치기"로 포커스). 있으면 확인 대화상자 |
| 다른 곳으로 이동 | 옆 메뉴·머리줄 링크 | Enter | 고친 칸이 있으면 확인 대화상자. "고친 내용 버리고 나가기"를 누르면 이동 |
| 브라우저 뒤로 | 뒤로 버튼 | Alt+← | 편집 모드에서 고친 칸이 있으면 기록을 되돌려 놓고 확인 대화상자. 버리면 보기 모드 |
| 새로고침·닫기 | — | ⌘R | 고친 칸이 있으면 브라우저 확인 창 |
| 대화상자 | 버튼 | Tab 은 안에서만, Esc 는 "닫기"와 같음 | 닫으면 연 요소로 포커스, 버리면 보기 모드 "고객 정보 고치기"로 포커스 |
| 배너 | 닫기 · 배너 안 버튼 | Enter | 닫으면 `focusNext` 자리로 포커스 |
| 화면 안 위치로 | 옆 메뉴 "이 고객" 링크 | Enter | 그 묶음으로 스크롤(편집 모드는 폼 묶음으로). 서랍이면 닫힌다 |
| 화면 밝기 | 묶음 버튼 | 화살표 · Home · End | 바로 바뀌고 저장(`ds-theme`) |

- 포커스 순서: 건너뛰기 → 머리줄 → 옆 메뉴 → 페이지 머리(고치기 버튼) → 배너 → 폼(위에서 아래) 또는 보기 묶음 → 주문 표 → 변경 기록.
- 단축키: 없음. 편집 중 Esc 로 폼을 닫지 않는다(입력을 잃을 수 있다).

## 10. 설계 메모 — 흔한 기본값과 비교

| 처음 안 | 흔한 기본값과 같은 점 | 바꾼 것 |
|---|---|---|
| 보기 모드를 "라벨: 값" 표 한 장으로 | 모든 값을 같은 무게로 나열(`PAT-DETAIL-03`·`SLOP-UI-08`) | 전화·이메일·주소는 값만 크게, 나머지 속성만 설명 목록 |
| 묶음마다 카드 상자 | 모든 영역을 테두리 상자로 감싼 구성 | 보기 모드는 제목 + 구분선. 카드는 편집 폼 하나에만 써서 "고치는 중"을 드러낸다 |
| 편집을 가운데 모달로 | 깊은 편집을 모달로(`PAT-ARC-04`) | 같은 페이지 안에서 보기 묶음을 폼으로 바꾼다. 주문·변경 기록은 옆에 남아 참고할 수 있다 |
| 저장 버튼을 모든 칸이 맞을 때까지 회색으로 | 미리 막은 제출 버튼(`SLOP-UI-14`) | 늘 누를 수 있고, 누르면 요약 + 첫 오류 칸 |
| 저장 성공을 토스트로 | 토스트 기본 알림(`CMP-FB-01`) | 값·변경 기록·마지막 수정 줄이 바로 바뀌고, 닫을 때까지 남는 성공 배너 하나 |
| 오류 요약에 칸 오류 문장을 다시 나열 | 같은 문장 두 번 | 요약에는 칸 이름 링크만, 이유는 칸 아래에 한 번 |
| 머리 아래 "C-0001 · 영업팀 · 2024-03-04" 메타 줄 | `SLOP-09` 메타 줄 | 마지막 수정을 문장 한 줄로, 나머지는 설명 목록 |
