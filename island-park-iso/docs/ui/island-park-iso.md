### 3-1. 그림 구성

모양은 3D 판과 같은 저폴리(면이 보이는 단순한 입체)와 납작한 음영이다. 그림 파일·텍스처 없이 모두 코드로 만든다. 섬 모양·나무 자리·명소 크기는 3D 판과 같은 좌표와 같은 씨앗 난수로 계산한다. 그래서 두 판의 배치가 같다.

| 항목 | 정한 것 |
|---|---|
| 보는 방향 | 남동쪽 위에서 내려본다(2:1 아이소메트릭, 내려보는 각 30°). 3D 판의 처음 시점(남동쪽, 35°)과 같은 쪽이다. 그래서 화면에서 선착장은 왼쪽 아래, 등대는 왼쪽 위, 대관람차는 위, 롤러코스터는 오른쪽에 보인다 |
| 면 밝기 | 햇빛은 3D 판의 해 자리(서남서쪽 위)에서 온다. 면마다 방향을 계산해 4단계(윗면 · 햇빛 쪽 · 비스듬한 면 · 그늘 면) 중 하나로 칠한다. 보이지 않는 면은 그리지 않는다 |
| 그리는 순서 | 바다 무늬 → 얕은 물 → 섬(비탈·덮개) → 길·광장·그림자 → 놓인 것들(나무·건물·놀이기구)을 뒤에서 앞으로. 롤러코스터 궤도는 조각 10개로 나눠 앞뒤를 정렬한다 |

| 요소 | 섬 위 위치 | 움직임 | 표지 |
|---|---|---|---|
| 섬 | 바다 한가운데. 가운데가 낮고 북쪽에 언덕 | 없음 | 없음 |
| 바다 | 그림 전체 바탕 + 섬 둘레 얕은 물 두 겹 | 짧은 물결 무늬가 옆으로 천천히 밀린다(주기 4초) | 없음 |
| 선착장과 배 | 남쪽 해안 | 배가 물결에 맞춰 위아래로 흔들린다 | 선착장 |
| 회전목마 | 섬 가운데 광장 | 말 여덟 마리가 돈다(한 바퀴 20초). 말이 위아래로 오르내린다 | 회전목마 |
| 대관람차 | 북쪽 언덕 위. 섬에서 가장 높다 | 바퀴가 돈다(한 바퀴 40초). 칸은 늘 아래로 매달려 있다 | 대관람차 |
| 롤러코스터 | 동쪽 해안을 따라. 궤도 일부가 바다 위로 나간다 | 차량 세 칸이 궤도를 따라 달린다(한 바퀴 12초) | 롤러코스터 |
| 등대 전망대 | 서쪽 끝 바위 | 꼭대기 불빛 두 줄기가 돈다(한 바퀴 8초) | 등대 전망대 |
| 길·나무·작은 건물(매표소·카페) | 명소 사이 | 없음 | 없음 |

낮과 밤은 같은 그림에 색만 바꾼다. 모양과 명소 위치는 같다. 색은 CSS 변수(`--iso-*`)로 칠하고, `html[data-time]` 이 그 변수만 바꾼다.

| 항목 | 낮(기본) | 밤 |
|---|---|---|
| 바다 | 파란 바다 + 옅은 얕은 물 | 짙은 남색 바다 |
| 섬·나무·건물 | 4-1절 낮 색 | 같은 재질을 달빛으로 어둡고 푸르게 |
| 놀이기구 | 흰 구조물 + 코랄 레드 | 같은 모양에 전구 불빛(따뜻한 노란색). 관람차 바퀴·회전목마 지붕 둘레·코스터 궤도 가장자리·선착장 가로등 |
| 건물 창 | 짙은 회청색 | 따뜻한 노란 불빛 |
| 등대 | 불빛 줄기가 옅게 돈다 | 불빛 줄기가 진하게 돈다 |
| 불빛 웅덩이(땅) | 보이지 않음 | 광장과 대관람차 언덕 위가 노란빛으로 옅게 밝아진다. 그라데이션 대신 원 두 겹을 겹친다 |
| 물에 비친 불빛 | 보이지 않음 | 선착장·롤러코스터·등대 앞 바다에 짧은 노란 선이 비친다. 처음에는 바다에도 원을 깔았지만 모래톱처럼 보여서 선으로 바꿨다 |
| 표지·패널 | 흰 표면 | 흰 표면 그대로(UI 는 다크 모드가 아니다) |

- 들어올 때는 늘 낮으로 시작한다. 고른 시간대를 저장하지 않는다.
- 낮·밤 전환은 그림 색을 600ms 에 바꾼다(감속 곡선). OS 움직임 줄이기가 켜져 있거나 움직임 멈춤이면 즉시 바꾼다.

### 3-2. 보는 범위(시점)

3D 판의 카메라 대신 SVG 의 `viewBox`(그림에서 화면에 보일 범위)를 바꾼다. 그림을 다시 그리지 않고 보이는 범위만 옮긴다.

| 항목 | 값 |
|---|---|
| 처음 시점 | 섬 그림 전체(명소 다섯 곳 포함)가 보이는 자리의 84% 를 채운다(가로·세로 중 빡빡한 쪽 기준). 보이는 자리 = 넓은 폭에서는 정보 패널이 가린 만큼 뺀 폭 × 위쪽 토글 아래부터 아래쪽 조작 버튼 위까지의 높이. 그 가운데에 둔다. 좁은 폭에서 버튼 두 줄이 섬을 가리지 않게 하려는 것이다. 글자를 키워 남는 높이가 40% 아래면 전체 높이를 쓴다 |
| 배율 제한 | 처음 배율의 0.56배(멀리 보기 2번) ~ 3.16배(가까이 보기 4번). 버튼 한 번에 4/3 배 |
| 가운데 제한 | 보이는 범위의 가운데는 섬 그림 범위 안에서만 움직인다. 섬이 화면 밖으로 사라지지 않는다 |
| 명소를 고르면 | 그 명소 그림과 표지가 보이는 자리 높이·폭의 50% 를 채우도록 확대·이동한다(600ms, 감속 곡선). 처음 배율보다 작아지지 않는다 |
| 기울기·회전 | 해당 없음 — 2D 그림은 보는 방향이 하나로 고정된다(6절 "섬 돌리기" 참고) |
| 자동 회전 | 해당 없음 — 돌릴 시점이 없다 |
| 인트로 | 없음. 첫 화면부터 처음 시점이다 |

#### 3D 판의 "돌리기" 버튼을 "옮기기" 버튼으로 바꾼 이유

- 3D 판에서 끌기는 섬을 돌린다. 그래서 끌기의 버튼 대안이 "왼쪽으로 돌리기 · 오른쪽으로 돌리기"였다.
- 2D 그림은 보는 방향이 하나다. 돌리려면 네 방향의 그림을 따로 그려야 하고, 돌릴 때마다 명소 자리가 바뀌어 3D 판과 비교하기도 어려워진다. 그래서 돌리기를 두지 않는다.
- 2D 에서 끌기는 그림을 옮긴다(가까이 보았을 때 다른 곳을 본다). 끌기로 하는 일에는 누르기만으로 하는 대안이 있어야 한다(`A11Y-WCAG-07`, WCAG 2.5.7). 그래서 돌리기 버튼 2개 자리에 옮기기 버튼 4개(왼쪽·위쪽·아래쪽·오른쪽 보기)를 둔다.
- 버튼 이름은 "가까이 보기 · 멀리 보기"와 같은 "~ 보기" 꼴로 맞췄다. "왼쪽 보기"는 지금보다 왼쪽에 있는 곳을 보여 준다(그림은 오른쪽으로 밀린다). 한 번에 보이는 폭(높이)의 1/4 만큼 400ms 에 옮긴다.

### 4-2. 기술 선택과 예산

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 그리기 | 인라인 SVG. `tools/build-scene.mjs`(Node, 의존성 없음)가 3D 판과 같은 좌표·씨앗 난수로 면을 계산해 `index.html` 의 표시 사이에 넣는다 | 그림이 HTML 과 함께 도착한다. 스크립트가 실패해도 그림이 보인다. 이미지 파일·포스터가 필요 없다 |

| 자바스크립트 꺼짐 | 그림(처음 범위, 멈춘 상태) + 명소 다섯 곳의 설명을 모두 펼쳐 보이고, 안내 배너를 띄운다. 넓은 폭에서는 그림을 패널 오른쪽 자리에 맞춘다 | 설명은 HTML 에 미리 넣고, 스크립트가 켜지면 고른 하나만 보인다 |

## 6. 상호작용

| 동작 | 마우스·터치 | 키보드 | 결과 |

| 조작 버튼 툴팁 | 마우스를 올리면 보인다. 툴팁 위로 포인터를 옮겨도 닫히지 않는다 | 포커스를 받으면 보인다. Esc 로 닫는다 | WCAG 1.4.13 |

| 밤으로·낮으로 바꾸기 | 토글 버튼 | Tab + Enter·Space | 색이 600ms 에 바뀐다(움직임 줄이기·멈춤이면 즉시). 라벨이 다음 행동으로 바뀐다. 포커스는 버튼에 그대로 있다 |
| 3D 로 보기 | 링크 클릭·탭 | Tab + Enter | 3D 판으로 이동한다 |
| 이동 중 다른 입력 | 확대·이동 중에 끌기·휠·두 손가락 | 이동 중에 다른 버튼 | 진행 중인 이동을 바로 취소하고 새 입력을 따른다 |

- 포커스 순서: 건너뛰기 링크 → 3D 로 보기 → 움직임 토글 → 낮·밤 토글 → 조작 버튼 7개 → 명소 목록 → 상세 안 요소(있으면). 좁은 폭의 화면 순서(상단 바 → 그림 → 목록)와 같다. 건너뛰기 링크는 바로 명소 목록으로 간다.
- 단축키: Esc 만 둔다. 보이는 툴팁이 있으면 툴팁을 닫고, 없으면 처음 시점으로 간다. 글자 한 개 단축키는 두지 않는다.
- 표지는 `aria-hidden="true"`, `tabindex="-1"` 로 둔다. 키보드와 화면낭독기는 목록으로 같은 일을 한다.
- 그림 `<svg>` 에는 `role="img"` 와 7절의 대체 텍스트를 단다. 그림 안의 면은 화면낭독기가 읽지 않는다.

## 10. 설계 메모 — 흔한 기본값과 비교

| 처음 안 | 흔한 기본값과 같은 점 | 바꾼 것 |
|---|---|---|
| 섬 그림을 이미지 파일(PNG·SVG 파일) 한 장으로 두고 확대만 하기 | 2D 지도 화면의 흔한 기본값이다. 놀이기구가 움직이지 않고, 밤 그림은 파일을 하나 더 받아야 한다 | 인라인 SVG 의 면을 CSS 변수로 칠한다. 밤은 변수만 바꾸고, 움직이는 부분 30여 개만 매 프레임 옮긴다 |
| 그림을 손으로 그린 납작한 일러스트 | 배치가 3D 판과 어긋나기 쉽고, 견줄 때 "같은 섬"으로 보이지 않는다 | 3D 판의 좌표·씨앗 난수로 면을 계산해 같은 배치를 만든다. 면 밝기도 3D 판의 해 방향으로 계산한다 |
| 반투명 유리(blur) 패널 | 그림 위에 얹는 패널의 흔한 기본값이다 | 3D 판과 같이 불투명 흰 표면 + 반투명 테두리 + 두 겹 그림자 |
| 밤 불빛에 방사형 그라데이션 후광(radial halo) | AI 기본 장식으로 꼽히는 빛 번짐이다(`SLOP-03`) | 땅에는 노란 원 두 겹을 낮은 투명도로 겹치고, 바다에는 물결처럼 짧은 노란 선을 둔다 |
| 3D 판의 "돌리기" 버튼을 그대로 두고 그림을 좌우 반전 | 버튼 수를 맞추려는 흔한 타협이다. 반전하면 동서가 바뀌어 위치 한 마디("동쪽 해안")와 어긋난다 | 돌리기를 없애고 끌기의 버튼 대안인 옮기기 4개를 둔다 |
| 명소마다 아이콘 타일이 붙은 카드 격자 | `SLOP-06`·`SLOP-07` 이 지목한 카드 키트다 | 3D 판과 같은 목록 행. 좁은 폭은 칩 |

- `MOT-01` 예외(3D 판과 같다): 명소로 확대·이동은 600ms 로 한다. 섬 반대편까지 가는 큰 이동을 400ms 에 끝내면 오히려 어지럽다(추정). 대신 감속 곡선을 쓰고(`MOT-04`), 입력이 오면 바로 취소하고(`MOT-10`), OS 움직임 줄이기가 켜지면 즉시 전환한다(`MOT-06`).
- `MOT-05` 예외: 낮·밤 전환에서 그림 면의 `fill`·`stroke` 색을 600ms 에 바꾼다. 3D 판이 빛과 색을 600ms 에 바꾸는 것과 같은 일이다. UI 요소(버튼·표지·패널)는 색을 애니메이션하지 않는다. 움직임 줄이기·멈춤이면 즉시 바꾼다.
- 위키 공백: 이 위키의 화면 유형 표에는 소비자용 첫 화면·그림 탐색 화면 유형이 없다. 3D 판과 같이 목록 + 상세로 옮겨 적었다.
