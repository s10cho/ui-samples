- 가로 휴대폰(높이 480 미만, 가로가 더 김): 장면은 왼쪽 60% 를 높이 전체로 채운다. 오른쪽 40% 에 목록과 상세를 두고 그 열만 스크롤한다.

### 3-1. 장면 구성

모양은 저폴리(면이 보이는 단순한 입체)와 납작한 음영으로 만든다. 장난감 모형처럼 보이게 한다. 모델·텍스처 파일은 쓰지 않고 모두 코드로 만든다. 실제 놀이공원의 특정 건물(성·관람차 디자인 등)을 본뜨지 않는다.

| 요소 | 섬 위 위치 | 움직임 | 표지 |
|---|---|---|---|
| 섬 | 바다 한가운데. 가운데가 낮고 북쪽에 언덕 | 없음 | 없음 |
| 바다 | 섬 둘레 전체, 안개 속 수평선까지 | 낮은 물결, 주기 약 4초 | 없음 |
| 하늘 | 단색 + 같은 색 안개. 수평선이 하늘에 녹아든다 | 없음 | 없음 |
| 선착장과 배 | 남쪽 해안. 첫 시점의 앞쪽 | 배가 물결에 맞춰 흔들린다 | 선착장 |
| 회전목마 | 섬 가운데 광장 | 천천히 돈다 | 회전목마 |
| 대관람차 | 북쪽 언덕 위. 섬에서 가장 높다. 첫 시점의 시선 끝 | 한 바퀴 약 40초 | 대관람차 |
| 롤러코스터 | 동쪽 해안을 따라. 궤도 일부가 바다 위로 나간다 | 열차 한 대가 궤도를 돈다. 한 바퀴 약 12초 | 롤러코스터 |
| 등대 전망대 | 서쪽 끝 바위 | 꼭대기 불빛이 돈다 | 등대 전망대 |
| 길·나무·작은 건물 | 명소 사이 | 없음 | 없음 |

낮과 밤은 같은 장면에 빛과 색만 바꾼다. 모양과 명소 위치는 같다.

| 항목 | 낮(기본) | 밤 |
|---|---|---|
| 하늘·안개 | 옅은 하늘색 단색 | 짙은 남색 단색 |
| 주 빛 | 오후 햇빛(남서쪽 위, 따뜻한 흰색) + 하늘빛 | 달빛(푸른 흰색, 약하게) + 하늘빛 |
| 놀이기구 | 흰 구조물 + 코랄 레드 | 같은 모양에 전구 불빛(따뜻한 노란색 자체 발광). 관람차 테두리·회전목마 지붕·코스터 궤도 가장자리·선착장 기둥 |
| 등대 | 불빛이 돈다(약하게 보임) | 불빛이 돌며 바다 위로 빛줄기가 보인다 |
| 바다 | 파란 물결 | 짙은 물결. 선착장·롤러코스터·등대 가까운 바다가 불빛으로 따뜻하게 밝아진다(따로 그리는 면 없이 물결 색을 데운다) |
| 표지·패널 | 흰 표면 | 흰 표면 그대로(UI 는 다크 모드가 아니다) |

- 들어올 때는 늘 낮으로 시작한다. 고른 시간대를 저장하지 않는다.
- 낮·밤 전환은 빛과 색을 600ms 에 바꾼다(감속 곡선). OS 움직임 줄이기가 켜져 있거나 움직임 멈춤이면 즉시 바꾼다.

### 3-2. 시점(카메라)

| 항목 | 값 |
|---|---|
| 처음 시점 | 남동쪽 위에서 비스듬히 내려본다(내려보는 각 약 35°). 섬 전체가 장면 폭의 60~70% 를 채운다. 선착장이 앞, 대관람차가 뒤 |
| 각도 제한 | 내려보는 각 15°~70°. 수평선 아래와 섬 밑면이 보이지 않게 한다 |
| 거리 제한 | 가장 가까이: 명소 하나가 장면 높이의 절반. 가장 멀리: 섬이 장면 폭의 40% |
| 중심점 제한 | 사용자가 중심점을 옮기는 조작이 없다. 중심점은 처음 시점과 명소 시점 사이에서만 움직인다 |
| 명소를 고르면 | 중심점을 그 명소로, 거리를 명소 크기에 맞춰 옮긴다. 세로로 긴 장면(가로÷세로 1.25 미만)에서는 최대 2배까지 멀리서 본다. 대관람차는 회전목마에 가리지 않게 남남서쪽에서 본다 |
| 자동 회전 | 처음 들어왔을 때만 아주 느리게(한 바퀴 약 90초). 사용자가 한 번 조작하면 끄고 다시 켜지 않는다 |
| 인트로 | 없음. 첫 프레임부터 처음 시점이다 |

- 포커스 순서: 건너뛰기 링크 → 움직임 토글 → 낮·밤 토글 → 시점 조작 버튼 5개 → 명소 목록 → 상세 안 요소(있으면). 좁은 폭의 화면 순서(장면 → 목록)와 같다. 건너뛰기 링크는 바로 명소 목록으로 간다.
- 단축키: Esc 만 둔다. 보이는 툴팁이 있으면 툴팁을 닫고, 없으면 처음 시점으로 간다. 글자 한 개 단축키는 두지 않는다.
- 표지는 `aria-hidden="true"`, `tabindex="-1"` 로 둔다. 키보드와 화면낭독기는 목록으로 같은 일을 한다. 탭 정지가 두 번 생기지 않는다.
- 장면 `<canvas>` 에는 `role="img"` 와 7절의 대체 텍스트를 단다.
- 좁은 폭에서 목록 항목에 포커스가 가도 고정 요소에 가려지지 않는다(고정 요소 없음). 넓은 폭의 떠 있는 패널은 포커스 요소를 가리지 않게 패널 안에서 스크롤한다.

| `STA-12` | 필수 | 선택 결과를 화면낭독기에 전달 |

| `WRT-BTN-01` | 필수 | 버튼 이름은 동사("돌리기"·"보기"·"멈추기") |

## 10. 설계 메모 — 흔한 기본값과 비교

| 처음 안 | 흔한 기본값과 같은 점 | 바꾼 것 |
|---|---|---|
| 화면 가운데 큰 제목 + "둘러보기" 버튼, 뒤에 3D 섬 | 가운데 정렬 히어로 + 버튼 하나는 랜딩 페이지의 가장 흔한 모양이다(`SLOP-15`). 글자가 장면 한가운데를 가린다 | 장면이 첫 화면 전체다. 제목은 왼쪽 패널로 옮겼다. 첫 행동은 버튼이 아니라 명소 고르기다 |
| 반투명 유리(blur) 패널 | 3D 화면 위에 얹는 패널의 흔한 기본값이다. 움직이는 장면 위에서 글자 대비가 프레임마다 바뀐다(`A11Y-WCAG-01`) | 불투명 흰 표면 + 반투명 테두리 + 두 겹 그림자 |
| 밤하늘 + 보라·청록 네온 조명 | `SLOP-01` 이 지목한 AI 기본 색이다 | 낮 장면. 강조색은 코랄 레드 하나. 장면 놀이기구 색과 UI 강조색을 같은 색으로 묶었다 |
| 하늘 그라데이션 | 장식 그라데이션 배경과 구분이 어렵다(`SLOP-03`) | 하늘은 단색 + 같은 색 안개. 수평선이 하늘에 녹아든다 |
| 밤 장면에 보라·청록 네온 + 빛 번짐(bloom) | 밤 3D 장면의 흔한 기본값이다(`SLOP-01`). bloom 은 휴대폰에서 비싸다 | 남색 하늘 + 따뜻한 노란 전구 하나. 후처리 없이 자체 발광 재질로만 그린다. UI 는 밤에도 흰 표면 그대로 |
| 진입할 때 멀리서 섬으로 날아드는 카메라 인트로 | 3D 첫 화면의 흔한 연출이다. 사용자를 기다리게 하고 어지럼을 줄 수 있다(`MOT-06`) | 인트로 없음. 첫 프레임부터 처음 시점. 아주 느린 자동 회전만 두고 첫 조작 때 끈다 |
| 명소마다 아이콘 타일이 붙은 카드 격자 | `SLOP-06`·`SLOP-07` 이 지목한 카드 키트다 | 이름 + 위치 한 마디의 목록 행. 좁은 폭은 칩 |
| `OrbitControls` 기본값 그대로 | 끝없이 돌고, 섬 밑면이 보이고, 휴대폰에서 장면을 만지면 페이지가 스크롤되지 않는다 | 각도·거리·중심점을 제한했다. 좁은·중간 폭은 가로 끌기만 회전, 세로 끌기는 스크롤 |
| 3D 로딩 중 가운데 스피너 | 기다림을 보이는 흔한 방법이다(`STA-14`) | 처음 시점과 같은 구도의 포스터 이미지를 먼저 보인다. 3D 가 실패해도 같은 이미지가 남는다 |

- `MOT-01` 예외: 시점 이동은 600ms 로 한다. `MOT-01` 은 UI 전환을 400ms 이하로 정한다. 3D 시점 이동을 400ms 에 끝내면 섬 반대편까지 도는 큰 회전이 너무 빨라 오히려 어지럽다(추정 — 구현 뒤 실제 기기에서 확인). 대신 감속 곡선을 쓰고(`MOT-04`), 입력이 오면 바로 취소하고(`MOT-10`), OS 움직임 줄이기가 켜지면 즉시 전환한다(`MOT-06`).
- 위키 공백: 이 위키의 화면 유형 표에는 소비자용 첫 화면·3D 화면 유형이 없다. 이 설계서는 목록 + 상세로 옮겨 적었다.
