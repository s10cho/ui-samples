## 1. 사용자와 할 일

| 항목 | 내용 | 확인 / 가정 |
|---|---|---|
| 사용자 | 작은 운영팀(5명)의 팀원과 팀장. 결제·배송·정산·고객 문의 업무를 카드로 나눠 맡는다 | 가정 — 작업 지시("업무 카드를 단계 열로 보는 보드") |
| 주요 작업 | ① 카드를 다음 단계로 옮긴다(끌어 놓기 또는 "옮기기" 메뉴) ② 개수 제한을 넘은 단계를 보고 막힌 곳을 푼다 ③ 담당자·라벨로 걸러 내 일만 본다 ④ 카드를 열어 내용과 활동 기록을 본다 | 확인 — 작업 지시 |
| 빈도 | 하루 여러 번, 한 번에 카드 몇 장 | 가정 |
| 들어오는 길 | 옆 메뉴의 "업무 보드", 공유받은 주소(필터·열린 카드·보기 그대로) | 가정 |
| 나가는 길 | 카드를 옮긴 뒤 그대로 보드에 남는다. 옆 메뉴로 다른 화면 | 가정 |

## 2. 정보 우선순위

| 순위 | 정보·행동 | 이 순위인 이유 |
|---|---|---|
| 1 | 단계 열과 그 안의 카드(제목·담당자·마감) | 무엇이 어디까지 왔는지가 보드의 첫 정보다(`PAT-LIST-01` — 카드는 사람이 읽는 제목으로 알아본다) |
| 2 | 열마다 카드 수와 개수 제한, 넘었을 때 경고 | 일이 막힌 단계를 바로 알아야 다음 행동(검토 먼저 끝내기)을 정한다 |
| 3 | 카드 옮기기(끌어 놓기 · "옮기기" 메뉴) | 이 화면에서 끝낼 행동이다 |
| 4 | 걸린 필터와 보이는 카드 수 | 필터가 걸린 줄 모르면 카드가 사라졌다고 오해한다(`PAT-LIST-03`) |
| 5 | 카드 상세(설명·활동 기록)와 카드 추가 | 필요할 때만 연다 |

- 주 행동: 카드 옮기기. 화면 전체에 강조색 채움 버튼을 두지 않는다 — 옮기기는 카드마다 있고, 카드 추가는 보조 버튼이다. 강조색 채움은 열린 카드 추가 폼의 "할 일에 추가" 하나뿐이다(`CMP-BTN-02`).

## 3. 영역 구성

새로 만드는 것과 이유:

- 단계 열·카드·놓일 자리 선·개수 제한 줄: kit 에 칸반 부품이 없다. 카드는 `ds-card`(카드 머리·제목 크기 16)보다 작고 촘촘해야 한다. 값은 모두 `--ds-*` 토큰을 쓴다.
- 끌어 놓기 동작: kit 에 없다. 포인터 이벤트(마우스·펜·터치 한 가지 코드)로 만든다. 터치는 길게 누르기(0.4초) 뒤에 끌기를 시작해 화면 스크롤과 다툼이 없게 한다.
- 샘플 토큰 3개(`css/page.css` 맨 위): `--kanban-board-col-min`(10rem — 4열이 되는 열 최소 폭), `--kanban-board-hold`(0.4초 — 터치 길게 누르기 시간, 움직임이 아니라 판단 시간이라 motion 토큰에 없다), `--kanban-board-edge`(3.5rem — 끄는 동안 화면 위·아래 이 거리 안에 들어오면 화면을 굴린다).
- 목록 보기를 표(`ds-table`) 대신 단계별 묶음 행으로 만든 이유: 행마다 "옮기기" 메뉴가 있는데 kit 표 틀(`ds-table-wrap`)은 `overflow: auto/clip` 이라 아래쪽 행의 메뉴가 잘린다. 단계 머리(개수·제한 줄)를 보드와 같은 모양으로 둘 수도 있다.
- kit 메뉴에 `aria-disabled` 항목 모양이 없어 샘플에서 흐린 글·금지 커서·고대비 GrayText 를 메웠다.
- 위 넷은 "공용 부품에 필요한 것"으로 보고한다(끌어 놓기 도우미, 칸반 열·카드 부품, 메뉴 비활성 항목, 메뉴를 담는 표 틀).

## 10. 설계 메모 — 흔한 기본값과 비교

| 처음 안 | 흔한 기본값과 같은 점 | 바꾼 것 |
