## 1. 사용자와 할 일

| 항목 | 내용 | 확인 / 가정 |
|---|---|---|
| 사용자 | 팀 업무 도구에 방금 가입한 팀의 첫 관리자. 이 화면을 처음이자 한 번 본다 | 가정 — 작업 지시("처음 가입한 팀") |
| 주요 작업 | ① 팀 이름·작업 공간 주소를 정한다 ② 구성원에게 초대 메일을 보낸다 ③ 문의가 들어올 채널을 연결한다. 셋 다 지금 하지 않아도 된다 | 확인 — 작업 지시 |
| 빈도 | 팀마다 한 번. 다 마치지 못하면 첫 화면 체크리스트에서 몇 번 더 들어온다 | 가정 |
| 들어오는 길 | 가입을 마친 직후(이 샘플에서는 샘플 목록 페이지) | 가정 |
| 나가는 길 | 4단계 "작업 공간 열기" 또는 각 단계 "나중에 하기" → 작업 공간 첫 화면(체크리스트) | 확인 — 작업 지시 |

- 위저드를 고른 이유: 팀마다 한 번 하는 드문 설정이다(`PAT-ARC-05`·`PRN-B2B-08` 의 금지 대상이 아니다). 처음 쓰는 사람에게 할 일의 순서를 보여 준다(NN/g 위저드 기준, `PAT-FORM-14`).
- 강제 튜토리얼이 아니다. 모든 단계를 건너뛸 수 있고, 남은 일은 첫 화면 체크리스트로 옮긴다(`PAT-AUTH-14`).

## 2. 정보 우선순위

| 순위 | 정보·행동 | 이 순위인 이유 |
|---|---|---|
| 1 | 지금 단계와 남은 단계, 끝낸 단계·건너뛴 단계(단계 표시) | 위저드는 단계 수·지금 단계·끝낸 단계를 보여야 한다(`PAT-FORM-12`). 건너뛴 단계가 끝낸 단계처럼 보이면 남은 일을 놓친다 |
| 2 | 이 단계에서 할 일과 건너뛰어도 되는지 | 처음 쓰는 사람은 "지금 꼭 해야 하나"를 먼저 묻는다 |
| 3 | 입력 칸과 오류, 고치는 법 | 칸 바로 아래에 둔다(`PAT-FORM-05`). 여러 개면 위에 오류 요약 |
| 4 | 초대·연결 결과(보냄·보내지 못함·연결됨·연결 실패) | 일부만 실패하면 무엇이 남았는지 알아야 다시 한다 |
| 5 | 진행이 이 창에 저장된다는 범위 안내 | 떠나기 전 경고 대신 쓰는 조건이다(DESIGN.md `PAT-FORM-11` 조건부 예외) |
| 6 | 마친 뒤 남은 일(체크리스트) | 건너뛴 일을 잃지 않게 다음 할 일로 남긴다 |

- 주 행동: 단계마다 하나 — "구성원 초대하기"(1) → "초대 보내기"(2) → "설정 내용 확인하기"(3) → "작업 공간 열기"(4). 첫 화면에는 주 버튼을 두지 않고 남은 일마다 보조 버튼을 둔다.

## 3. 영역 구성

| 체크리스트 | 첫 화면 본문 | 진행("3개 중 2개 끝냈어요" + 막대), 남은 일·끝낸 일 3줄, 남은 일마다 보조 버튼 | `ds-card` `ds-progress` + 체크리스트 줄(샘플 CSS) | 줄 안 버튼이 글 아래로 | 버튼이 줄 오른쪽 | 같음 |

- 옆 메뉴는 두지 않는다(`ds-app--bare`). 설정을 마치기 전에는 옮겨 갈 다른 메뉴가 없고, 가짜 메뉴 링크를 두지 않는다.
- 본문 한 열은 최대 40rem 이고 가운데에 둔다. 1280 에서 폼 칸을 화면 전체로 늘리지 않는다(`LAY-04`). 입력 칸은 kit `--ds-size-field-max`(480)까지.

- 새로 만든 것과 이유: kit 에 입력 뒤 고정 글(주소 접미사), 여러 칸을 늘리고 줄이는 입력 줄, 상태와 버튼이 붙은 줄 목록, 건너뛴 단계 표시가 없다. 모두 kit 토큰만 쓴다.
- 샘플 토큰(`css/page.css` 맨 위 `:root`): `--onboarding-setup-col-max` 40rem(본문 한 열 — 1280 에서 폼이 화면 가운데에 모이게, `LAY-04`). 체크리스트 원·아이콘은 kit `--ds-icon-size-lg`(20)를 쓴다.
- kit 메움(샘플 CSS, 공용 부품에 필요한 것): 알림 배너는 kit 에서 아이콘·본문·닫기 3열이라 320 + 글자 200% 에서 본문 열이 16px 남짓으로 줄어 한 글자씩 접혔다. 배너 자리(`ds-banner-slot`)에 `container-type: inline-size` 를 주고, 자리가 20rem 보다 좁으면 첫 줄에 아이콘·닫기, 다음 줄에 본문 전체 폭을 둔다(측정: 본문 198px).

## 5. 상태

| 상태 | 언제 | 보이는 것 | 문구 | 사용자 행동 | 확인 방법 |
|---|---|---|---|---|---|
| 초기 로딩 | 해당 없음 — 가입 때 받은 팀 이름·주소는 페이지와 함께 온다. 서버를 기다리는 첫 화면이 없다(`STA-14`) | — | — | — | — |
| 부분 로딩(초대 보내는 중) | 2단계 "초대 보내기"를 누른 뒤(흉내 1.5초). `?state=sending` 이면 끝나지 않는다 | 버튼은 바로 다시 누를 수 없고, 0.3초 뒤 회전 표시 + "보내는 중…"(`DS.busy`). 이메일 칸·역할은 보내는 동안 고칠 수 없다(`fieldset disabled`). 이전 단계·건너뛰기·나중에 하기도 보내는 동안 `aria-disabled` + 이유("초대를 다 보내면 누를 수 있어요.", 툴팁 + `aria-describedby`) — 보내는 사이 건너뛰면 "건너뜀"과 "보냄"이 섞인다(1회차 지적) | "보내는 중…" | 기다린다 | `?state=sending` |
| 부분 로딩(채널 연결 중) | 3단계 "연결하기"를 누른 뒤(흉내 1.5초) | 그 줄 버튼만 "연결 중…"(`DS.busy`). 다른 채널은 그대로 누를 수 있다 | "연결 중…" | 기다린다 | 연결하기 누름 |
| 빈 화면(처음 사용) | 첫 화면에서 남은 일이 있을 때 | 체크리스트가 곧 빈 작업 공간의 안내다. 남은 일마다 채우는 행동 버튼 | "구성원 초대하기"·"채널 연결하기" | 버튼 → 그 단계 | `?view=home` |
| 빈 화면(조건 결과 없음) | 해당 없음 — 검색·필터가 없다 | — | — | — | — |

## 10. 설계 메모 — 흔한 기본값과 비교

| 처음 안 | 흔한 기본값과 같은 점 | 바꾼 것 |
|---|---|---|
| 4단계 끝에 큰 체크 아이콘 + "축하해요!" + 색종이 | 온보딩 완료 화면의 흔한 장식(AI 티, 작업 지시 금지) | 마지막 화면은 결과 목록 + 다음 할 일. 첫 화면은 체크리스트 |
| 단계 표시가 끝낸 단계와 건너뛴 단계를 같은 체크로 보임 | 대부분의 스테퍼가 "지나간 단계"를 한 모양으로 칠한다 | 건너뛴 단계는 `minus` + 점선 + 숨긴 글 "건너뜀". 색만으로 나누지 않는다 |
| 이메일 칸 줄마다 역할 고르기 | 초대 화면의 흔한 줄 구성 | 320 폭에서 칸이 너무 좁아진다. 역할을 묶음 하나로 빼고 "역할은 나중에 바꿀 수 있어요"는 쓰지 않는다(권한 화면이 이 샘플에 없다) |
| 초대 결과를 성공 토스트로 | 흔한 기본값 | 모두 보내면 다음 단계로 가는 것이 결과다. 일부 실패만 배너 + 칸 오류 |
| 첫 화면을 지표 카드 4개로 | 큰 숫자 카드 나열(AI 티) | 처음 가입한 팀은 숫자가 없다. 체크리스트 카드 하나 |
| 1280 에서 폼을 왼쪽에 붙임 | 업무 화면 기본 배치 | 옆 메뉴 없는 한 줄 흐름이라 40rem 열을 가운데에 둔다 |

- 1단계 "건너뛰기": 팀 이름은 작업 공간에 꼭 있어야 한다. 그래서 칸에 가입 때 적은 이름을 미리 넣고, 건너뛰면 그 이름을 쓴다(그 단계는 "건너뜀"). 칸에 고친 값은 이 창에 남아 다시 들어오면 보인다.
- 이메일 칸 이름: 화면에 보이는 이름은 묶음 이름 "초대할 사람의 이메일"과 칸 앞 번호 "1"이다. 칸의 접근 가능한 이름은 `aria-label` "1번째 이메일"이고 보이는 번호로 시작한다(WCAG 2.5.3). 처음에는 숨긴 글 "번째 이메일"을 번호 뒤에 이었는데, 숨긴 글이 블록이라 이름이 "1 번째 이메일"로 띄어 계산돼 `aria-label` 로 바꿨다.
