# 화면 설계서 — 운영 대시보드

| 항목 | 값 |
|---|---|
| 화면 id | ops-dashboard |
| 상태 | 초안(기본안 채택 — 사용자 일괄 위임 2026-11-17) |
| 작성일 | 2026-11-17 |
| 플랫폼 | 웹(일반 HTML·CSS·JS, 빌드 없음). 파일로 열어도 동작 |
| 밀도 | compact(터치 화면은 누르는 영역 44) |
| DESIGN.md | 있음 — 저장소 루트 `DESIGN.md`(2026-11-17 첫 판, 「샘플 데이터」 절 포함) |
| Context Pack | 5. 대시보드·관리자 화면(대시보드 · 데이터 표 · 목록 화면을 읽었다. 설정 화면은 해당 없음) |
| 화면 유형 | 대시보드(주) + 목록(보조, 알림 목록) — `PAT-ARC-01` |

가상 쇼핑몰의 운영 현황을 보는 화면이다. 서비스 이름은 두지 않는다. 수치·알림은 모두 가상이고 `js/data.js` 한 곳에서 결정적으로 만든다(DESIGN.md 「샘플 데이터」). 화면의 "지금"은 2026년 11월 17일(화) 14:00 이고, 화면을 열어 둔 시간만큼 앞으로 간다. 시각은 24시간제("14:00")로 쓴다.

## 1. 사용자와 할 일

| 항목 | 내용 | 확인 / 가정 |
|---|---|---|
| 사용자 | 온라인 서비스의 운영 담당자(당번), 팀장 | 가정 — 작업 지시("가상 온라인 서비스의 운영 현황 대시보드") |
| 주요 작업 | ① 지금 문제가 있는지 판단한다(목표를 벗어난 지표, 확인하지 않은 알림) ② 알림을 확인 처리한다 ③ 언제부터 나빠졌는지 추세로 본다 | 확인 — 작업 지시(지표 카드·추세 그래프·알림 확인·기간 선택·자동 새로고침) |
| 빈도 | 당번은 화면을 켜 두고 하루 내내 본다. 팀장은 하루 몇 번 기간을 바꿔 본다 | 가정 |
| 들어오는 길 | 옆 메뉴 "운영 현황", 알림 메시지의 링크(주소에 `alerts` 가 없으면 "확인 안 함" 탭) | 가정 |
| 나가는 길 | 알림 확인 뒤 같은 화면에 머문다. 옆 메뉴의 "샘플 목록" | 가정 |

## 2. 정보 우선순위

| 순위 | 정보·행동 | 이 순위인 이유 |
|---|---|---|
| 1 | 데이터가 최신인지(마지막 갱신 시각, 데이터 지연 경고) | 늦은 숫자로 판단하면 틀린다. 지연은 모든 숫자의 뜻을 바꾼다 |
| 2 | 목표를 벗어난 지표 — 지표 4개의 현재 값, 목표 대비 상태, 앞 기간 대비 변화 | "지금 문제가 있나"에 가장 빨리 답한다 |
| 3 | 확인하지 않은 알림(심각도·시각·내용)과 확인 처리 | 운영 담당자가 이 화면에서 직접 끝내는 일이다(`PAT-DASH-01` 의 "지금 처리할 일") |
| 4 | 언제부터 바뀌었는지 — 추세 그래프 3개(주문 수, 응답 시간, 오류율) | 원인을 찾을 때 시점을 본다 |
| 5 | 기간 바꾸기, 그래프를 표로 보기, 자동 새로고침 멈추기 | 보는 범위·방식을 바꾸는 보조 조작이다 |

- 주 행동: 알림 "확인 처리". 이 화면에 강조색 채움 버튼은 두지 않는다. 알림 행 버튼은 보조 버튼이고, 행이 여러 개라 주 버튼 하나로 모을 수 없다(`PAT-ARC-02`, `CLR-07`).

## 3. 영역 구성

DOM 순서 = 좁은 폭에서 한 열로 접히는 순서다(`PAT-DASH-04`): 머리줄 → 옆 메뉴 → 페이지 머리(제목·갱신 상태) → 기간 도구 줄 → 배너 자리 → 지표 띠 → 알림 → 추세 → 바닥줄.

| 영역 | 위치 | 담는 것 | 컴포넌트 | 좁은 폭(375) | 중간 폭(768) | 넓은 폭(1280 이상) |
|---|---|---|---|---|---|---|
| 건너뛰기 링크 | 맨 앞 | "본문으로 건너뛰기" | `ds-skip-link` | 같음 | 같음 | 같음 |
| 머리줄 | 위, 붙음 | 메뉴 버튼, "UI 샘플" 링크, 화면 밝기 고르기 | `ds-topbar` `ds-segmented` | 밝기는 아이콘만(툴팁) | 메뉴 버튼 보임 | 메뉴 버튼 숨김 |
| 옆 메뉴 | 왼쪽 | 운영(운영 현황 — 지금 화면) · 이 화면(지표·알림·추세 앵커) · 이 저장소(샘플 목록·부품 모음) | `ds-sidenav` | 서랍 | 서랍 | 왼쪽 240 |
| 페이지 머리 | 본문 맨 위 | 제목 "운영 현황", 설명 한 줄, 갱신 상태(마지막 갱신 시각 · 지연 배지 · 자동 새로고침 스위치 · "지금 새로고침") | `ds-page__head` `ds-switch` `ds-btn` `ds-badge--warning` | 제목 아래로 갱신 상태가 줄바꿈 | 같음 | 제목 오른쪽 |
| 기간 도구 줄 | 페이지 머리 아래 | 기간 고르기(오늘·7일·30일·직접), 고른 기간의 날짜 범위 글, "직접"일 때 시작일·종료일·"기간 적용" | `ds-segmented` `ds-input[type=date]` `ds-btn` | 묶음 버튼 한 줄, 날짜 칸은 아래로 쌓음 | 한 줄 | 한 줄 |
| 배너 자리 | 도구 줄 아래(스크롤 영역 밖) | 데이터 지연, 확인 처리 실패(불러오기 오류는 결과 자리의 `ds-empty--error`) | `ds-banner-slot` | 같음 | 같음 | 같음 |
| 지표 띠 | 본문 | 주문 수 · 매출 · 응답 시간 · 오류율. 칸마다 이름, 값, 앞 기간 대비, 목표 대비 | 테두리 하나 안을 구분선으로 나눈 띠(카드 4장이 아니다) | 1열 4칸 | 2열 × 2줄 | 4열 1줄(띠 폭 56rem 이상) |
| 알림 | 지표 띠 아래 | 탭(확인 안 함 · 이 기간 전체), 심각도 요약, 알림 행(심각도 배지 · 영역 · 시각 · 내용 · 상태 · "확인 처리" 버튼). 틀이 20rem 보다 좁으면 버튼을 글 아래로 내린다 | `ds-card--flush` `ds-tabs` `ds-list` `ds-badge` `ds-btn--sm` | 전체 폭, 높이 제한 없음 | 같음 | 왼쪽 22rem 열, 머리줄 아래에 붙음(sticky), 최대 높이 min(40rem, 화면 높이) + 안쪽 스크롤(`PAT-DASH-07`) — 그래프를 스크롤해 보는 동안 알림 열이 빈 칸으로 남지 않게 |
| 추세 | 알림 옆(넓은 폭) / 아래(좁은 폭) | 그래프 3개를 한 틀에 구분선으로 나눔. 그래프마다 제목 · 요약 한 줄 · 범례 · "그래프/표" 고르기 · 그래프 또는 표 | `ds-card` 하나 + 샘플 부품 `ops-chart`(인라인 SVG) + `ds-table` | 그래프 폭 = 화면 폭, 축 눈금 수를 줄임 | 같음 | 오른쪽 남은 폭 |
| 바닥줄 | 본문 맨 아래 | "이 화면의 지표·알림은 모두 가상의 샘플 데이터예요." | kit `ds-sample-note`(정보 아이콘 + 캡션 글) | 같음 | 같음 | 같음 |

- 넓은 폭 배치는 페이지가 아니라 본문 폭으로 나눈다(컨테이너 쿼리). 본문 안쪽 폭이 60rem 이상이면 "지표 띠(위 전체) / 알림(왼쪽) + 추세(오른쪽)" 두 열이다. 글자를 200% 로 키우면 rem 이 함께 커져 한 열로 돌아간다.
- 알림을 왼쪽 열에 두는 이유: DOM 순서(지표 → 알림 → 추세)와 화면 읽는 순서(위 → 왼쪽 → 오른쪽)를 맞추려고. 오른쪽에 두면 키보드 포커스가 오른쪽 열을 먼저 돈 뒤 왼쪽으로 돌아온다.

새로 만드는 것과 이유:

- **추세 그래프** — kit 에 그래프 부품이 없다. 차트 라이브러리는 쓰지 않는다(작업 지시). `js/chart.js` 가 SVG 를 그린다. 그래프 폭을 재서 viewBox 를 실제 픽셀과 같게 두므로 글자가 그래프와 함께 줄지 않는다.
- **지표 띠** — `ds-grid` + `ds-card` 4장은 같은 모양 카드를 늘어놓은 화면이 된다(`SLOP-06`·`PAT-DASH-11`). 테두리 하나 안을 구분선으로 나누면 4칸이 한 묶음으로 읽힌다.
- **그래프 색** — kit 2회차의 `--ds-color-series-1`(밝게 `#2a78d6`, 어둡게 `#3987e5`)을 쓴다. 0회차에 샘플 토큰으로 두었던 같은 값이다. 강조색(`fill-accent`)은 그래프에 쓰지 않는다(DESIGN.md).

## 5. 상태
