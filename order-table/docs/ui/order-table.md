## 1. 사용자와 할 일

| 항목 | 내용 | 확인 / 가정 |
|---|---|---|
| 사용자 | 온라인 판매 주문을 처리하는 운영 담당자 | 확인 — 작업 지시("운영자가 주문을 찾고 한꺼번에 처리") |
| 주요 작업 | ① 조건(기간·배송 상태·검색어)으로 주문을 찾는다 ② 여러 건을 골라 한꺼번에 배송 처리하거나 취소한다 ③ 결과(처리한 건수·건너뛴 건수)를 확인한다 | 확인 — 작업 지시 |
| 빈도 | 하루 여러 번, 한 번에 수 건에서 수십 건 | 가정 |
| 들어오는 길 | 옆 메뉴의 "주문 목록", 공유받은 주소(필터가 걸린 채로) | 가정 |
| 나가는 길 | 처리 결과 배너를 보고 다음 조건으로 다시 찾는다. 옆 메뉴로 다른 화면 | 가정 |

## 2. 정보 우선순위

| 순위 | 정보·행동 | 이 순위인 이유 |
|---|---|---|
| 1 | 주문 행 — 주문 번호, 고객, 배송 상태, 결제 상태 | 처리할 주문을 알아보고 고르는 것이 첫 일이다 |
| 2 | 걸린 필터와 결과 건수 | 필터가 걸린 줄 모르면 주문이 빠졌다고 오해한다(`PAT-LIST-03`) |
| 3 | 고른 건수와 일괄 작업(배송 처리·주문 취소) | 이 화면에서 끝낼 행동이다 |
| 4 | 찾기 도구(검색어·기간·배송 상태) | 매번 쓰지만, 결과가 먼저 보여야 조건을 고칠지 판단한다 |
| 5 | 쪽 위치("120건 중 21–40")와 열 고르기 | 넘겨 보거나 표를 고칠 때만 본다 |

- 주 행동: 고른 주문 배송 처리(일괄 작업 줄의 강조 버튼 하나). 주문 취소는 보조 버튼 + 위험 확인 대화상자(`CMP-BTN-02`).

## 4. 컴포넌트

| 컴포넌트 | 기존 / 새로 | 변형 | 쓰는 토큰 | 관련 규칙 |
|---|---|---|---|---|
| 앱 틀·옆 메뉴·머리줄 | 기존 | 서랍 | `surface-canvas` `surface-selected` | `CMP-NAV-06` `CMP-NAV-11` `CMP-NAV-14` |
| 검색·고르기·날짜 입력 | 기존 `ds-search` `ds-select` `ds-input` | — | `line-control` `line-danger` | `CMP-INPUT-01` `CMP-INPUT-02` `CMP-INPUT-07` |
| 배송 상태 칩 | 기존 `ds-chip[aria-pressed]` + `ds-count` | 켜짐 = 체크 + 테두리 | `fill-accent-subtle` | `CMP-SEL-04` `CMP-SEL-09` |
| 걸린 필터 칩 | 기존 `ds-chip--input` | — | `surface-subtle` | `PAT-LIST-03` |
| 버튼 | 기존 `ds-btn` | primary(배송 처리) · 보조 · ghost · danger(대화상자 안 취소) | `fill-accent` `fill-danger` | `CMP-BTN-02` `CMP-BTN-09` `CMP-BTN-10` |
| 표 | 기존 `ds-table` `ds-table--stack` `ds-sort` `ds-num` | 쌓기 | `surface-subtle` `fill-accent-subtle` | `CMP-TABLE-*` |
| 배지 | 기존 `ds-badge` | accent · info · success · warning · 기본 | `fill-*-subtle` | `CMP-TABLE-14` `CMP-SEL-08` |
| 알림 배너 | 기존 `DS.banner` | success · danger · info | `fill-*-subtle` | `STA-09` `CMP-FB-14` |
| 빈 상태 | 기존 `ds-empty--center`(표 안 빈 행 `ds-table__empty`) | — | `fg-muted` | `STA-07` `STA-08` |
| 스켈레톤 행 | 기존 `ds-table__skeleton` | — | `surface-hover` | `CMP-FB-09` |
| 대화상자 | 기존 `ds-dialog--sm` | — | `surface-raised` `surface-overlay` | `CMP-OVL-08` `CMP-OVL-09` |
| 쪽 나누기 | 기존 `ds-pagination` | 480 미만 줄임 | `fill-accent-subtle` | `CMP-TABLE-09` |
| 필터 서랍 | **새로**(샘플 CSS `ot-drawer`) | 오른쪽 전체 높이 | `surface-raised` `shadow-overlay` | `CMP-OVL-08` `CMP-OVL-12` |
| 열 고르기 | **새로**(샘플 CSS `ot-colmenu`) | 체크박스 여러 개를 켜고 끄는 펼침 상자 | `surface-raised` `shadow-overlay` | `CMP-TABLE-07` |

- 필터 서랍을 새로 만드는 이유: kit 대화상자는 가운데에 뜨는 확인용이다. 좁은 폭에서 필터 여러 개를 세로로 놓을 오른쪽 서랍 변형이 없다. `<dialog>`·`DS.dialog` 를 그대로 쓰고 모양만 샘플 CSS 로 바꾼다.
- 열 고르기를 새로 만드는 이유: kit 메뉴(`[aria-haspopup="menu"]`)는 항목을 누르면 닫힌다. 열 여러 개를 연달아 켜고 끄려면 닫히지 않는 펼침 상자(disclosure)가 필요하다. 버튼 `aria-expanded` + 체크박스 묶음(`fieldset`)으로 만든다.
- 둘 다 오케스트레이터 보고의 "공용 부품에 필요한 것"으로 올린다.

| 부분 로딩 | 일괄 작업을 확인한 뒤, "새 주문 확인"을 눌렀을 때 | 누른 버튼만 "처리 중…" + 회전 표시, 표 틀 `aria-busy`. 다른 영역은 그대로 | "처리 중…" | 기다린다 | 배송 처리 실행 뒤 버튼 `aria-busy` |

## 10. 설계 메모 — 흔한 기본값과 비교

| 처음 안 | 흔한 기본값과 같은 점 | 바꾼 것 |
|---|---|---|
| 표 위에 "오늘 주문 / 배송 대기 / 매출" 지표 카드 3장 | 큰 숫자 + 작은 라벨 카드 줄(`SLOP` 대시보드 첫 영역) | 지표 카드 없음. 같은 정보는 배송 상태 칩의 건수로 보인다(누르면 바로 걸러진다) |
| 행마다 "배송 처리"·"취소"·"더 보기" 아이콘 버튼 | 행 끝 동작 여러 개(`PAT-LIST-07`) | 행 안 동작 없음. 체크박스 + 표 위 일괄 작업 하나로 모은다 |
| 배송 상태를 탭(전체·배송준비·…)으로 | 탭은 하나만 고른다 | 여러 개를 켜는 칩. 운영자는 "배송준비 + 입금대기 아닌 것"처럼 묶어 본다 |
| 일괄 작업 실패·성공을 화면 아래 토스트로 | 토스트 기본 알림(`CMP-FB-01`) | 배너 자리의 남는 배너. 건너뛴 이유를 함께 쓴다 |
| 확인 대화상자에 "정말 하시겠어요?" + "확인/취소" | 질문형 일반 문구, "취소" 버튼 | 무엇이 몇 건 바뀌는지와 건너뛸 이유를 쓰고, 버튼은 "닫기" · "주문 4건 배송 처리" |
| 좁은 폭에서 표를 가로 스크롤로만 | 열이 7개라 375 에서 한 화면에 한두 열만 보인다 | 카드로 쌓고(kit `--stack`), 필터는 서랍으로 옮겨 검색 칸만 남긴다 |
| 걸린 필터를 필터 칸 안에서만 표시 | 서랍을 닫으면 걸린 조건이 안 보인다 | 걸린 필터 줄을 서랍 밖에 늘 둔다 |
