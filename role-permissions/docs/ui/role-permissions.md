## 1. 사용자와 할 일

| 항목 | 내용 | 확인 / 가정 |
|---|---|---|
| 사용자 | 업무 서비스(상담·주문을 다루는 팀용 웹)의 팀 관리자. 구성원은 이 화면을 보기만 한다 | 확인 — 작업 지시(역할 목록 ↔ 구성원 보기, 권한 표). 사용자 구성은 가정 |
| 주요 작업 | ① 역할을 골라 기능 묶음마다 보기·만들기·고치기·지우기·내보내기를 켜고 끈 뒤, 바뀐 곳을 확인하고 저장한다 ② 위험한 권한(지우기·결제·내보내기)을 켤 때 한 번 더 확인한다 ③ 구성원에게 역할을 준다 ④ 역할의 변경 내역을 본다 | 확인 — 작업 지시 |
| 빈도 | 드물다. 사람이 들고 날 때(주 몇 번 역할 주기), 업무가 바뀔 때(달 몇 번 권한 표 고치기) | 가정 |
| 들어오는 길 | 옆 메뉴 "권한 관리", 설정 화면 팀 탭, 초대 메일 확인 뒤 역할을 주러(`?view=members`) | 가정 |
| 나가는 길 | 옆 메뉴로 다른 업무 화면. 저장하지 않은 변경이 있으면 먼저 묻는다 | 가정 |

## 2. 정보 우선순위

| 순위 | 정보·행동 | 이 순위인 이유 |
|---|---|---|
| 1 | 지금 고른 역할과 그 역할이 할 수 있는 일(권한 표) | 관리자의 첫 질문은 "이 역할이 무엇을 할 수 있나"다 |
| 2 | 저장하지 않은 변경이 몇 곳인지, 무엇이 바뀌는지 | 권한은 저장하는 순간 구성원 여럿에게 바로 적용된다. 저장 전에 확인해야 한다 |
| 3 | 위험한 권한(지우기·결제·환불·내보내기) | 잘못 주면 되돌리기 어렵다. 표 머리에 글자 표시로 늘 보인다 |
| 4 | 이 역할을 가진 구성원 수 | 바꾼 권한이 몇 명에게 적용되는지 안다 |
| 5 | 고칠 수 없는 역할(기본 역할)과 그 이유 | 막힌 이유를 모르면 고장으로 안다 |
| 6 | 변경 내역(언제·누가·무엇을) | 문제가 생겼을 때 거슬러 본다. 자주 보지 않으니 표 아래 |

- 주 행동: 영역마다 하나(`PAT-ARC-02`) — 역할 보기 "변경 내용 저장", 구성원 보기는 행마다 역할 고르기(바로 적용, 채운 버튼 없음).

### 저장 방식(설계 결정)

| 묶음 | 방식 | 이유 |
|---|---|---|
| 권한 표 | 체크를 바꾸면 바로 "바뀐 곳"으로 모으고, "변경 내용 저장"으로 한 번에 적용 | 권한 하나만 바꾸는 일은 드물다. 여러 칸을 고친 뒤 미리 보고 저장해야 중간 상태가 구성원에게 닿지 않는다. 체크박스라 스위치처럼 바로 적용될 거라고 오해하지 않는다(`PAT-SET-02`) |
| 위험한 권한 켜기 | 켜기 전에 확인 대화상자. 끄기는 묻지 않는다 | 권한을 넓히는 쪽이 위험하다. 끄기는 저장 전 미리 보기에서 함께 확인한다 |
| 보기와 다른 권한의 관계 | 만들기·고치기·지우기·내보내기를 켜면 보기도 켜고, 보기를 끄면 그 줄의 나머지도 끈다. 함께 바뀐 칸도 "바뀐 곳"에 센다 | 볼 수 없는 것을 고칠 수는 없다. 표 위 범례 한 줄로 미리 알리고, 바꿀 때 live 영역으로 읽는다 |
| 구성원 역할 | 고르는 즉시 적용. 관리자로 올릴 때만 확인 대화상자. 권한을 낮추면 배너에 "되돌리기" | 한 사람의 역할 바꾸기는 단순하고 결과가 행에 바로 보인다(`STA-10`). 관리자는 위험한 권한을 모두 가진다. 권한 회수는 되돌리기를 준다(`PAT-SET-04`) |

- 저장하지 않은 변경이 있는 채로 다른 역할을 고르거나, 구성원 탭으로 옮기거나(kit `ds:tabbeforechange` 를 취소), 옆 메뉴 링크로 나가려 하면 대화상자로 묻는다: 닫기 · 변경 버리고 이동 · 저장하고 이동. 창 닫기·새로고침은 브라우저 기본 확인(`beforeunload`).
- `PAT-FORM-11` 의 sessionStorage 조건부 예외는 쓰지 않는다. 권한은 저장 여부를 묻는 편이 맞다(설정 샘플과 같은 판단).

## 5. 상태

상태 쿼리는 `?state=`. 역할은 `?role=`, 보기는 `?view=members` 로 함께 준다.
