### 3-1. 그림 구성

모양은 3D 판과 같은 저폴리(면이 보이는 단순한 입체)와 납작한 음영이다. 그림 파일·텍스처 없이 모두 코드로 만든다. 산 높이 함수·슬로프 길·명소 자리·나무 자리는 3D 판(`js/scene/scene.js`)과 같은 식과 같은 씨앗 난수로 계산한다. 그래서 두 판의 배치가 같다.

| 항목 | 정한 것 |
|---|---|
| 투영 | 원근 없는 평행 투영. 내려보는 각 30°(아이소메트릭과 같다. 땅의 앞뒤 길이가 절반으로 보인다) |
| 보는 방향 | 3D 판 처음 시점과 같은 남남동쪽(남쪽에서 동쪽으로 20°). 그래서 산장과 광장이 앞(아래), 정상이 위 가운데, 초급 슬로프가 오른쪽, 상급 슬로프가 왼쪽, 리프트가 그 사이에 보인다 |
| 땅 | 보는 방향에 맞춘 엇갈린 세모 격자(한 칸 2. 홀수 줄의 꼭짓점을 반 칸 옆으로 민다)로 높이 함수를 잰다. 세모마다 한 색. 처음에 네모 칸을 둘로 나눴더니 땅 색 경계가 가로 계단처럼 보여 엇갈린 격자로 바꿨다. 보이지 않는 면(산 뒤쪽)은 그리지 않는다. 골짜기 바닥 세모도 그리지 않는다 — 아래 깔린 골짜기 바닥 판이 그 자리를 칠한다(낮은 둔덕의 면을 그리면 땅 가장자리가 계단처럼 보인다). 같은 줄·같은 색 세모는 `<path>` 하나로 묶는다 |
| 땅 색 | 3D 판과 같은 조건: 가파른 면은 바위, 높은 곳 일부도 바위, 나무 선 아래는 숲 바닥, 산 둘레 낮은 곳은 골짜기 바닥, 나머지는 눈. 슬로프 길과 광장의 다진 눈은 땅 세모가 아니라 매끈한 띠·타원으로 덮는다(세모 크기 2 로는 길 폭이 들쭉날쭉해진다) |
| 면 밝기 | 햇빛은 3D 판의 해 자리(남서쪽 위, `(-24, 30, 22)`)에서 온다. 면마다 해 쪽 기울기를 계산해 4단계(윗면 · 햇빛 쪽 · 비스듬한 면 · 그늘 면) 중 하나로 칠한다. 단계 색은 3D 판의 해·하늘빛 세기로 계산했다(4-1절) |
| 그리는 순서 | 하늘(바탕) → 안개 띠 두 겹과 먼 산 → 골짜기 바닥 → 땅을 뒤에서 앞으로 한 줄(앞뒤 폭 2)씩. 줄마다 땅 세모 → 다진 눈 띠 → 그림자 → 그 줄에 서 있는 것(나무·막대·건물·리프트 철탑과 줄·의자·스키어) 순서. 움직이는 의자·스키어는 지금 서 있는 줄로 옮겨 그린다 |
| 같은 모양 되풀이 | 평행 투영이라 같은 물건은 어디에 있어도 같은 모양이다. 나무(크기 3가지)·의자(오르는 쪽·내려오는 쪽)는 한 번 그려 두고 자리만 바꿔 쓴다(`<symbol>`·`<use>`) |

| 요소 | 산 위 위치 | 움직임 | 표지 |
|---|---|---|---|
| 산(땅) | 그림 한가운데. 정상은 가운데에서 조금 북쪽. 서쪽에 낮은 봉우리, 동쪽에 능선 | 없음 | 없음 |
| 골짜기 바닥 | 산 둘레의 평평한 눈밭. 바깥으로 갈수록 안개 띠 두 겹을 지나 하늘색에 녹는다 | 없음 | 없음 |

### 3-2. 보는 범위(시점)

3D 판의 카메라 대신 SVG 의 `viewBox`(그림에서 화면에 보일 범위)를 바꾼다. 그림을 다시 그리지 않고 보이는 범위만 옮긴다. 바다 위 놀이공원 2D 판과 같은 식이다.

| 항목 | 값 |
|---|---|
| 처음 시점 | 산 그림 범위(땅·명소·표지 자리. 안개 띠와 먼 산은 뺀다)가 보이는 자리의 84% 를 채운다(가로·세로 중 빡빡한 쪽 기준). 보이는 자리 = 넓은 폭에서는 정보 패널이 가린 만큼 뺀 폭 × 위쪽 토글 아래부터 아래쪽 조작 버튼 위까지의 높이. 그 가운데에 둔다. 글자를 키워 남는 높이가 40% 아래면 전체 높이를 쓴다 |
| 배율 제한 | 처음 배율의 0.56배(멀리 보기 2번) ~ 3.16배(가까이 보기 4번). 버튼 한 번에 4/3 배 |
| 가운데 제한 | 보이는 범위의 가운데는 산 그림 범위 안에서만 움직인다. 산이 화면 밖으로 사라지지 않는다 |
| 명소를 고르면 | 그 명소 그림과 표지가 보이는 자리 높이·폭의 70% 를 채우도록 확대·이동한다(600ms, 감속 곡선). 처음 배율보다 작아지지 않고 3.16배를 넘지 않는다. 2D 판(50%)보다 키운 까닭: 리프트·두 슬로프는 산 높이만큼 길어 50% 로는 거의 확대되지 않는다(리프트 1.03배). 70% 면 리프트가 약 1.4배로, 3D 판에서 리프트를 고를 때 다가가는 정도(거리 약 0.7배)와 비슷하다 |
| 기울기·회전 | 해당 없음 — 2D 그림은 보는 방향이 하나로 고정된다(9절) |
| 자동 회전 | 해당 없음 — 돌릴 시점이 없다 |
| 인트로 | 없음. 첫 화면부터 처음 시점이다 |

- 3D 판의 "돌리기" 버튼 대신 "옮기기" 버튼 4개를 둔다. 이유는 바다 위 놀이공원 2D 판 설계서 3-2절과 같다: 2D 그림은 보는 방향이 하나이고, 2D에서 끌기는 그림을 옮긴다. 끌기에는 누르기만으로 하는 대안이 있어야 한다(`A11Y-WCAG-07`). 한 번에 보이는 폭(높이)의 1/4 만큼 400ms 에 옮긴다.

- 눈송이 크기·빠르기(UI 토큰이 아니다): 바둑판 한 칸 `--iso-flake-tile-near` 180px · `--iso-flake-tile-mid` 140px · `--iso-flake-tile-far` 110px. 한 번 되풀이에 오른쪽으로 한 칸, 아래로 네 칸 옮긴다(바람에 약 14° 기울어 떨어진다. 바둑판이 한 칸마다 되풀이되므로 이음매가 없다). 네 칸 떨어지는 시간 `--iso-flake-fall-near` 18s · `--iso-flake-fall-mid` 22s · `--iso-flake-fall-far` 28s(초당 약 40 · 25 · 16px). 눈송이 지름은 가까운 겹 4 · 가운데 겹 3 · 먼 겹 2, 한 칸에 7 · 9 · 9개(`tools/build-scene.mjs` 의 `FLAKES`. 바둑판 한 칸 값은 토큰과 같아야 한다).
- 강조색은 녹슨 주황빛 빨강 하나다. 리프트 의자·지붕·막대·스키어 옷과 선택된 표지를 묶는다(3D 판과 같다). 보라·청록 네온, 하늘 그라데이션을 쓰지 않는다(`SLOP-01`·`SLOP-03`). 안개도 그라데이션 대신 띠 두 겹으로 녹인다.
- 그림 안에는 글자를 두지 않는다. 이름은 모두 불투명 표지 위에 있다.

- 단축키: Esc 만 둔다. 보이는 툴팁이 있으면 툴팁을 닫고, 없으면 처음 시점으로 간다. 글자 한 개 단축키는 두지 않는다.
- 표지는 `aria-hidden="true"`, `tabindex="-1"` 로 둔다. 키보드와 화면낭독기는 목록으로 같은 일을 한다.
- 그림 `<svg>` 에는 `role="img"` 와 7절의 대체 텍스트를 단다. 날씨가 바뀌면 대체 텍스트도 바뀐다. 그림 안의 면과 눈송이 층은 화면낭독기가 읽지 않는다.

## 10. 설계 메모 — 흔한 기본값과 비교

| 처음 안 | 흔한 기본값과 같은 점 | 바꾼 것 |
|---|---|---|
| 산 그림을 이미지 파일 한 장으로 두고 확대만 하기 | 2D 지도 화면의 흔한 기본값이다. 의자·스키어가 움직이지 않고, 눈 내림 그림은 파일을 하나 더 받아야 한다 | 인라인 SVG 의 면을 CSS 변수로 칠한다. 날씨는 변수만 바꾸고, 움직이는 부분 26개만 매 프레임 옮긴다 |
| 손으로 그린 납작한 산 일러스트(삼각형 봉우리 몇 개) | 배치가 3D 판과 어긋나고, 견줄 때 "같은 산"으로 보이지 않는다 | 3D 판의 높이 함수·슬로프 길·씨앗 난수로 면을 계산해 같은 배치를 만든다. 면 밝기도 3D 판의 해 방향·빛 세기로 계산한다 |
| 표준 아이소메트릭 방향(남동쪽 45°)으로 그리기 | 아이소메트릭 그림의 흔한 기본값이다. 이 산에는 격자에 맞춘 건물이 거의 없어 45° 로 둘 까닭이 없고, 3D 판 처음 화면과 다른 모습이 먼저 보인다 | 내려보는 각은 아이소메트릭과 같은 30° 로 두고, 보는 방향은 3D 판 처음 시점(남남동쪽 20°)에 맞췄다 |

바다 위 놀이공원 2D 판 검수의 "고치면 좋은 것"과 3D 샘플 공통 뼈대의 지적 가운데 처음부터 반영한 것:

| 지적 | 이 설계에서 |
|---|---|
| 휠이 확대하지 않는 폭에서도 "휠로 가까이" 안내가 보인다 | 안내를 넓은 폭 마우스 · 좁은·중간 폭 마우스 · 좁은·중간 폭 터치 · 넓은 폭 터치 네 갈래로 나눴다. 휠 안내는 휠이 확대하는 조건(넓은 폭 + 마우스)에서만 보인다(7절) |
| 스크립트가 없을 때 목록 버튼이 누를 수 있게 보이지만 아무 일도 하지 않는다 | 스크립트가 없을 때 목록은 `#detail-<id>` 로 가는 링크다. 화면 스크립트가 켜지면 버튼으로 바꾼다(4절) |
| 표지 숨김 판정을 버튼 묶음 전체 경계 상자로 해서, 버튼과 겹치지 않는 표지도 숨는다 | 토글·조작 버튼 하나하나의 경계 상자와 겹칠 때만 숨긴다(3절) |
| 그림 투명도 토큰 하나가 설계서 표에 없다 | 그림에 쓰는 색·투명도 토큰을 4-1절 표에 모두 적었다 |
| 떠 있는 패널 안 테두리 행이 카드 안 카드로 읽힌다 | 위 표 "그림자 패널 안에 테두리 목록 행" 줄 |
| 비어 있는 live 영역을 `display:none` 으로 두어 접근성 트리에서 빠진다 | 배너 자리(`aria-live`)는 늘 렌더링한다. 스크립트가 돌 때는 화면에서만 감추고(`sr-only` 방식), 안쪽 배너만 숨긴다 |
| 배너를 지울 때 포커스가 사라진다 | 해당 없음 — 이 판의 배너는 지워지지 않는다(5절) |
| 로딩 중에도 조작 안내가 보이거나, 상태에 따라 고르는 법 안내가 사라진다 | 로딩 상태가 없다. 고르는 법 안내는 스크립트가 있을 때와 없을 때 모두 그 상태에 맞는 문구로 보인다(7절) |
| 멈춘 장면과 포스터의 대체 텍스트가 둘 겹친다 | 해당 없음 — 그림은 SVG 하나뿐이다(5절) |
| 글자 200% 의 좁은 폭에서 조작 버튼이 산 가운데를 덮는다 | 좁은·중간 폭에서는 버튼 사이 빈 띠가 40% 가 되도록 그림 높이를 늘린다(3절 산 그림) |

- `MOT-01` 예외(3D 판과 같다): 명소로 확대·이동은 600ms 로 한다. 산 반대편까지 가는 큰 이동을 400ms 에 끝내면 오히려 어지럽다(추정). 대신 감속 곡선을 쓰고(`MOT-04`), 입력이 오면 바로 취소하고(`MOT-10`), OS 움직임 줄이기가 켜지면 즉시 전환한다(`MOT-06`).
- `MOT-05` 예외: 날씨 전환에서 그림 면의 `fill`·`stroke` 색을 600ms 에 바꾼다. 3D 판이 빛과 색을 600ms 에 바꾸는 것과 같은 일이다. UI 요소(버튼·표지·패널)는 색을 애니메이션하지 않는다. 움직임 줄이기·멈춤이면 즉시 바꾼다.
- 위키 공백: 이 위키의 화면 유형 표에는 소비자용 첫 화면·그림 탐색 화면 유형이 없다. 3D 판과 같이 목록 + 상세로 옮겨 적었다.
