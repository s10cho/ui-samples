- 가로 휴대폰(높이 480 미만, 가로가 더 김): 장면은 왼쪽 60% 를 높이 전체로 채운다. 오른쪽 40% 에 목록과 상세를 두고 그 열만 스크롤한다.
- 넓은 폭에서 휠은 확대에 쓴다(페이지가 스크롤되지 않는다). 좁은·중간 폭에서는 휠을 페이지 스크롤에 두고, 확대는 버튼과 두 손가락 집기로만 한다. 조작 안내 문구도 이 조건에 맞춰 고른다(7절).
- 장면 위에 얹는 글자는 모두 불투명 표면 위에 둔다. 움직이는 장면 위 글자는 프레임마다 대비가 바뀌기 때문이다. 눈 입자는 3D 장면 안에서만 그리고 UI 위로 떨어지지 않는다.

### 3-1. 장면 구성

모양은 저폴리(면이 보이는 단순한 입체)와 납작한 음영으로 만든다. 장난감 모형처럼 보이게 한다. 모델·텍스처 파일은 쓰지 않고 모두 코드로 만든다. 실제 스키장의 산 모양·슬로프 배치·건물을 본뜨지 않는다. 가상의 산이다.

| 요소 | 산 위 위치 | 움직임 | 표지 |
|---|---|---|---|
| 산(지형) | 장면 한가운데. 정상은 가운데에서 조금 북쪽. 서쪽에 낮은 봉우리, 동쪽에 능선. 높이 함수로 평면 격자(`PlaneGeometry`)의 꼭짓점을 올린다 | 없음 | 없음 |
| 지형 색 | 삼각형마다 한 색. 높이와 기울기로 나눈다: 가파른 면은 바위, 나무 선 위는 눈, 나무 선 아래는 숲 바닥. 슬로프 길과 광장은 다진 눈 | 없음 | 없음 |
| 골짜기 바닥 | 산 둘레의 평평한 눈밭. 안개 속 지평선까지 | 없음 | 없음 |
| 먼 산 | 둘레 멀리 낮은 산 여러 개. 안개에 흐려진다 | 없음 | 없음 |
| 리프트 | 산 아래 광장(남쪽)에서 정상 바로 아래까지 곧게. 철탑 몇 개 + 줄 두 가닥 + 위아래 정류장 | 의자가 한 줄로 오르고 다른 줄로 내려온다. 한 바퀴 약 60초 | 리프트(줄 위쪽 3분의 2 지점. 줄 가운데에 달면 상급 슬로프 표지와 겹친다 — 구현 때 바꿈) |
| 초급 슬로프 | 남동쪽 비탈. 넓고 완만하게 S자로 굽는다 | 스키어 2명이 S자로 내려온다. 한 번에 약 22초 | 초급 슬로프 |
| 상급 슬로프 | 남서쪽 비탈. 정상 가까이에서 곧고 가파르게 | 스키어 2명이 내려온다. 한 번에 약 11초 | 상급 슬로프 |
| 산장 | 산 아래 광장. 두 슬로프가 끝나는 곳 | 없음 | 산장 |
| 정상 전망대 | 산꼭대기 | 없음 | 정상 전망대 |
| 나무 | 나무 선 아래 숲. 슬로프·리프트 길·광장은 비운다. 뾰족한 침엽수 + 꼭대기 눈. 숲은 산 둘레 타원 안에만 둔다(지형 격자의 네모난 끝이 드러나지 않게) | 없음 | 없음 |
| 슬로프 가장자리 막대 | 두 슬로프 양쪽 가장자리에 띄엄띄엄. 강조색 작은 막대(구현 때 추가 — 멀리서도 슬로프 길이 보이게) | 없음 | 없음 |
| 눈 입자 | 산 둘레 공간 | 눈 내림일 때 천천히 떨어지며 옆으로 조금 흔들린다 | 없음 |

맑음과 눈 내림은 같은 장면에 빛·색·안개·입자만 바꾼다. 모양과 명소 위치는 같다.

| 항목 | 맑음(기본) | 눈 내림 |
|---|---|---|
| 하늘·안개 | 옅은 겨울 하늘색 단색. 안개가 멀다 | 흐린 회청색 단색. 안개가 가까워 먼 산이 흐려진다. 가까운 산과 명소는 또렷하게 남긴다 |
| 주 빛 | 낮은 겨울 해(남서쪽 위, 따뜻한 흰색) + 하늘빛. 그림자가 또렷하다 | 흐린 날 빛(약하고 차가운 흰색) + 하늘빛을 키운다. 면 사이 명암 차가 줄어든다 |
| 눈 입자 | 보이지 않는다 | 흰 입자가 떨어진다. 높은 품질 2,400개, 낮은 품질 900개 |
| 표지·패널 | 흰 표면 | 흰 표면 그대로(UI 는 날씨와 상관없다) |

- 들어올 때는 늘 맑음으로 시작한다. 고른 날씨를 저장하지 않는다.
- 맑음·눈 내림 전환은 빛·색·안개·입자 투명도를 600ms 에 바꾼다(감속 곡선). OS 움직임 줄이기가 켜져 있거나 움직임 멈춤이면 즉시 바꾼다.
- 움직임을 멈추면 눈 입자도 그 자리에 멈춘다. 입자는 보이되 떨어지지 않는다.

### 3-2. 시점(카메라)

| 항목 | 값 |
|---|---|
| 처음 시점 | 남남동쪽 위에서 비스듬히 내려본다(내려보는 각 약 24°). 산 전체가 장면 폭의 60~70% 를 채운다. 산장과 광장이 앞, 정상이 시선 끝 |
| 각도 제한 | 내려보는 각 12°~65°. 지평선 아래와 지형 바깥 끝이 보이지 않게 한다 |
| 거리 제한 | 가장 가까이: 명소 하나가 장면 높이의 절반. 가장 멀리: 산이 장면 폭의 40% |
| 중심점 제한 | 사용자가 중심점을 옮기는 조작이 없다. 중심점은 처음 시점과 명소 시점 사이에서만 움직인다 |
| 명소를 고르면 | 중심점을 그 명소로, 거리를 명소 크기에 맞춰 옮긴다. 세로로 긴 장면(가로÷세로 1.25 미만)에서는 최대 2배까지 멀리서 본다. 상급 슬로프는 남서쪽, 초급 슬로프는 남동쪽에서 본다 |
| 자동 회전 | 처음 들어왔을 때만 아주 느리게(한 바퀴 약 90초). 사용자가 한 번 조작하면 끄고 다시 켜지 않는다 |
| 인트로 | 없음. 첫 프레임부터 처음 시점이다 |
| 첫 프레임 | 포스터를 찍은 장면 시각과 같은 시각에서 시작한다. 포스터에서 실시간 장면으로 바뀔 때 의자·스키어 자리가 튀지 않는다 |

## 4. 컴포넌트

프로젝트가 비어 있어 기존 컴포넌트가 없다. 아래는 모두 새로 만든다. 모양과 동작은 첫 3D 샘플과 같다.

### 4-2. 기술 선택과 예산

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 3D 라이브러리 | Three.js 0.187.0(MIT). 앱 코드가 쓰는 클래스만 한 파일로 묶어 `vendor/three/` 에 둔다(`tools/build-three.mjs`). 눈 입자용 `Points`·`PointsMaterial`·`CanvasTexture` 를 더한다 | CDN 장애와 외부 요청을 없앤다. 원본 두 파일은 압축 전송 약 420KB 라 예산을 넘는다 |

- 포커스 순서: 건너뛰기 링크 → 움직임 토글 → 날씨 토글 → 시점 조작 버튼 5개 → 명소 목록 → 상세 안 요소(있으면). 좁은 폭의 화면 순서(장면 → 목록)와 같다. 건너뛰기 링크는 바로 명소 목록으로 간다.
- 단축키: Esc 만 둔다. 보이는 툴팁이 있으면 툴팁을 닫고, 없으면 처음 시점으로 간다. 글자 한 개 단축키는 두지 않는다.
- 표지는 `aria-hidden="true"`, `tabindex="-1"` 로 둔다. 키보드와 화면낭독기는 목록으로 같은 일을 한다. 탭 정지가 두 번 생기지 않는다.
- 장면 `<canvas>` 에는 `role="img"` 와 7절의 대체 텍스트를 단다. 날씨가 바뀌면 대체 텍스트도 바뀐다. 3D가 보이지 않는 loading·lost·fallback 에서는 캔버스에 `aria-hidden="true"` 를 주고, ready 에서는 포스터 쪽에 준다. 같은 이름의 그림이 접근성 트리에 두 번 나오지 않는다.
- 배너를 지우거나 바꿀 때 포커스가 배너 안에 있었으면, 장면 토글 가운데 보이는 첫 버튼으로 옮긴다. 보이는 토글이 없으면 명소 목록 머리(`#landmarks`, `tabindex="-1"`)로 옮긴다. 포커스가 body 로 떨어지지 않는다(`moveFocusAfterBanner()`).
- live 영역(배너 자리 `aria-live`, 진행 문구 `role="status"`)은 비어 있어도 렌더링해 두고 화면에서만 숨긴다. `display:none` 을 쓰지 않는다.
- 좁은 폭에서 목록 항목에 포커스가 가도 고정 요소에 가려지지 않는다(고정 요소 없음). 넓은 폭의 떠 있는 패널은 포커스 요소를 가리지 않게 패널 안에서 스크롤한다.

## 10. 설계 메모 — 흔한 기본값과 비교

| 처음 안 | 흔한 기본값과 같은 점 | 바꾼 것 |
|---|---|---|

| 진입할 때 멀리서 산으로 날아드는 카메라 인트로 | 3D 첫 화면의 흔한 연출이다. 사용자를 기다리게 하고 어지럼을 줄 수 있다(`MOT-06`) | 인트로 없음. 첫 프레임부터 처음 시점. 아주 느린 자동 회전만 두고 첫 조작 때 끈다 |

첫 3D 샘플 검수의 "고치면 좋은 것" 가운데 처음부터 반영한 것:

| 지적 | 이 설계에서 |
|---|---|
| 폭 1024 미만 마우스 기기에 "휠로 가까이" 안내가 보이지만 그 폭에서 휠은 확대하지 않는다 | 조작 안내를 넓은 폭 마우스 · 좁은·중간 폭 마우스 · 터치 세 갈래로 나눴다(7절) |
| 포스터와 실시간 장면의 움직이는 물체 자리가 교체 순간 다르다 | 실시간 장면을 포스터와 같은 장면 시각에서 시작한다(3-2절 "첫 프레임") |
| 한 줄 배너의 문구와 닫기 버튼 세로 중심이 어긋난다 | 닫기 버튼 가운데를 문구 첫 줄 가운데에 맞춘다(4절 배너) |
| 그림자 패널 안 테두리 행이 카드 안 카드로 읽힌다 | 위 표 마지막에서 두 번째 줄 |

- `MOT-01` 예외: 시점 이동과 날씨 전환은 600ms 로 한다. `MOT-01` 은 UI 전환을 400ms 이하로 정한다. 3D 시점 이동을 400ms 에 끝내면 산 반대편까지 도는 큰 회전이 너무 빨라 오히려 어지럽다(추정 — 실제 기기에서 확인). 대신 감속 곡선을 쓰고(`MOT-04`), 입력이 오면 바로 취소하고(`MOT-10`), OS 움직임 줄이기가 켜지면 즉시 전환한다(`MOT-06`).
- 위키 공백: 이 위키의 화면 유형 표에는 소비자용 첫 화면·3D 화면 유형이 없다. 이 설계서는 목록 + 상세로 옮겨 적었다.
