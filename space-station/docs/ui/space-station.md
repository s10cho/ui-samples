## 1. 사용자와 할 일

| 항목 | 내용 | 확인 / 가정 |
|---|---|---|
| 사용자 | 우주 정거장에 관심이 있는 일반 방문자 | 가정 — 요청에 사용자 설명이 없다 |
| 주요 작업 | ① 지구 위를 도는 정거장의 전체 모습을 본다 ② 명소 하나를 골라 위치와 설명을 본다 ③ 지구의 낮 쪽과 밤 쪽을 바꿔 본다 | 요청("지구 궤도를 도는 가상의 우주 정거장을 3D로 보여 주는 첫 화면", "낮 쪽 ↔ 밤 쪽")에서 정함 |
| 빈도 | 방문 한 번에 몇 분, 명소 2~5곳을 본다 | 가정 |
| 기기 | 휴대폰 방문이 많다. 그래서 성능 예산은 휴대폰 기준으로 잡는다 | 가정 |
| 들어오는 길 | 샘플 목록 페이지의 링크로 들어온다 | 가정 |
| 나가는 길 | 없음 — 첫 화면 한 장이고 바깥 링크를 두지 않는다 | 열린 질문 5번 기본안 |

## 2. 정보 우선순위

| 순위 | 정보·행동 | 이 순위인 이유 |
|---|---|---|
| 1 | 지구 위에 떠 있는 정거장의 전체 모습(3D 장면) | 방문자의 첫 판단은 "여기는 어떤 곳인가"다. 장면이 그 답이다 |
| 2 | 명소 5곳의 이름과 정거장 안 위치 | 장면을 본 다음 "무엇이 있나"를 찾는다. 표지와 목록이 같은 정보를 준다 |
| 3 | 고른 명소의 설명 | 관심 가는 곳을 고른 뒤에 필요하다 |
| 4 | 지구 낮 쪽 ↔ 밤 쪽 바꾸기 | 장면 분위기를 크게 바꾸지만 명소 고르기보다 앞서지 않는다. 장면 안 오른쪽 위 토글로 둔다 |
| 5 | 둘러보는 방법(끌기·확대·버튼) | 처음 한 번 필요하다. 강제 튜토리얼 대신 맥락 안내로 준다 |
| 6 | 움직임 멈추기 | 대부분은 안 쓰지만, 어지럼을 느끼는 사람에게는 꼭 필요하다. 별이 반짝이고 지구가 도는 화면이라 더 중요하다. 항상 같은 자리에 둔다 |

- 주 행동(primary action): 명소 고르기.

- 가로 휴대폰(높이 480 미만, 가로가 더 김): 장면은 왼쪽 60% 를 높이 전체로 채운다. 오른쪽 40% 에 목록과 상세를 두고 그 열만 스크롤한다.
- 넓은 폭에서 휠은 확대에 쓴다(페이지가 스크롤되지 않는다). 좁은·중간 폭에서는 휠을 페이지 스크롤에 두고, 확대는 버튼과 두 손가락 집기로만 한다.
- 장면 위에 얹는 글자는 모두 불투명 표면 위에 둔다. 움직이는 장면 위 글자는 프레임마다 대비가 바뀌기 때문이다. 표면은 낮 쪽·밤 쪽 모두 같은 어두운 표면이다.
- **처음 시점의 빈 자리**: 장면 토글 묶음과 시점 버튼 묶음이 차지하는 실제 높이(글자 크기에 따라 바뀐다)를 장면 높이에서 빼고, 남은 띠의 가운데에 정거장을 맞춘다. 넓은 폭은 정보 패널 폭도 뺀다. 글자 200% 에서 버튼이 두 줄이 되어도 정거장이 버튼에 깔리지 않는다(`ski-mountain` 검수 4절 3번).

### 3-1. 장면 구성

모양은 저폴리(면이 보이는 단순한 입체)와 납작한 음영으로 만든다. 장난감 모형처럼 보이게 한다. 모델·텍스처 파일은 쓰지 않고 모두 코드로 만든다. **실존 정거장·우주 기관·우주선을 본뜨지 않는다.** 정거장 구성(가운데 마디 + 앞뒤 원통 둘 + 양옆 날개 한 쌍씩 + 끝의 둥근 관측 창)은 이 샘플이 지어낸 가상의 정거장이다. 이름·깃발·기관 표지를 넣지 않는다.

좌표: 정거장 가운데 마디가 원점. x 는 정거장이 나아가는 쪽(앞), y 는 위(지구 반대쪽), z 는 옆. 지구는 아래(−y)에 있다.

| 요소 | 정거장 안 위치 | 움직임 | 표지 |
|---|---|---|---|
| 가운데 마디 | 원점. 짧은 굵은 원통. 위에 작은 안테나 접시 | 없음 | 없음 |
| 거주 모듈 | 마디 앞쪽(+x)으로 길게 뻗은 흰 원통. 옆면에 둥근 창이 줄지어 있다. 금빛 단열 띠 | 없음. 밤 쪽에서 창에 불이 켜진다 | 거주 모듈 |
| 실험실 모듈 | 마디 뒤쪽(−x)으로 뻗은 원통. 위에 바깥 실험 상자 셋 | 없음 | 실험실 모듈 |
| 태양 전지판 | 마디에서 양옆(±z)으로 뻗은 뼈대에 날개 두 장씩, 모두 네 장. 남색 칸 + 금빛 틀 | 해를 따라 날개 각도를 천천히 바꾼다(주기 약 40초, ±14°) | 태양 전지판 — 카메라에 가까운 쪽 날개에 붙는다 |
| 도킹 포트 | 거주 모듈 앞 끝. 좁아지는 목 + 둥근 고리 | 없음. 밤 쪽에서 고리 둘레 불이 켜진다 | 도킹 포트 |
| 관측 창 | 실험실 모듈 뒤 끝. 지구 쪽으로 기운 둥근 창(여섯 면 + 꼭대기 창) | 없음. 밤 쪽에서 창 안이 따뜻하게 밝다 | 관측 창 |
| 화물선 | 도킹 포트 앞쪽 먼 곳 ↔ 도킹 포트 | 앞쪽에서 천천히 다가와 붙고, 잠시 머문 뒤 물러난다(한 바퀴 약 60초) | 없음 |
| 위치 표시등 | 양옆 날개 뼈대 끝. 한쪽 붉은빛, 한쪽 초록빛 | 2.4초 주기로 천천히 밝아졌다 어두워진다(번쩍이지 않는다) | 없음 |
| 지구 | 정거장 아래. 둥근 지평선이 장면 위쪽을 가로지른다 | 아주 느리게 돈다(한 바퀴 약 60분). 구름 층은 조금 더 빨리 돈다(약 25분) | 없음 |
| 대기 띠 | 지구 둘레의 얇은 띠 | 없음 | 없음 |
| 별 | 지평선 위 우주 | 하나하나 천천히 반짝인다(주기 1.5~4초) | 없음 |

지구 낮 쪽과 밤 쪽은 같은 장면에 빛과 색만 바꾼다. 모양과 명소 위치는 같다.

| 항목 | 낮 쪽(기본) | 밤 쪽 |
|---|---|---|
| 지구 표면 | 밝은 바다(짙은·옅은 파랑 두 가지) + 낮은 채도의 초록·황토 땅 | 아주 어두운 남색 바다와 땅. 땅 위에 도시 불빛(따뜻한 노란 점)이 켜진다 |
| 구름 | 흰 구름 조각 | 어두운 회청색, 흐리게 |
| 대기 띠 | 옅은 하늘색 띠 | 짙은 남색 띠 |
| 주 빛 | 해(따뜻한 흰빛, 위 왼쪽 앞) + 지구에서 올라오는 푸른 반사광 | 아주 약한 달빛(푸른 흰색) + 거의 없는 반사광 |
| 정거장 창·도킹 고리 | 어두운 유리, 불 꺼짐 | 거주 모듈 창·관측 창 안쪽·도킹 고리 불이 켜진다(따뜻한 노란색) |
| 태양 전지판 | 해를 받아 밝은 강철빛 남색 | 거의 검은 남색. 뼈대 뿌리의 작은 상태 등만 보인다 |
| 도킹 포트 조명 | 없음 | 도킹 포트 앞을 비추는 작업등 하나(점광원) |
| 별 | 흐리게(투명도 0.45) | 또렷하게 |
| 표지·패널 | 어두운 표면 | 어두운 표면 그대로(UI 는 두 상태 모두 같다) |

- 들어올 때는 늘 낮 쪽으로 시작한다. 고른 상태를 저장하지 않는다(열린 질문 1번).
- 낮 쪽 ↔ 밤 쪽 전환은 빛과 색을 600ms 에 바꾼다(감속 곡선). OS 움직임 줄이기가 켜져 있거나 움직임 멈춤이면 즉시 바꾼다.
- 움직임을 멈추면 별 반짝임·지구 회전·전지판·화물선·위치 표시등이 모두 그 자리에 멈춘다. 별은 보이되 반짝이지 않는다. 위치 표시등은 켜진 채로 멈춘다.

### 3-2. 시점(카메라)

| 항목 | 값 |
|---|---|
| 처음 시점 | 앞 오른쪽 위에서 비스듬히 내려본다(내려보는 각 약 24°, 방위 35°). 정거장 전체가 빈 자리 폭의 약 70% 를 채운다. 도킹 포트와 화물선이 앞, 관측 창이 뒤. 둥근 지평선이 장면 위쪽 약 1/4 지점을 가로지르고 그 위가 별이 있는 우주다 |
| 각도 제한 | 내려보는 각 8°~65° |
| 거리 제한 | 가장 가까이: 거주 모듈 하나가 장면 높이의 절반을 넘지 않는다(실효 거리 19, 실측 약 40%). 가장 멀리: 처음 거리의 1.6배. 실효 거리 = 카메라 거리 ÷ 렌즈 배율 |
| 중심점 제한 | 사용자가 중심점을 옮기는 조작이 없다. 중심점은 처음 시점과 명소 시점 사이에서만 움직인다 |
| 명소를 고르면 | 중심점을 그 명소로, 거리를 명소 크기에 맞춰 옮긴다. 명소 시점 거리도 가장 가까운 거리보다 가깝지 않다. 세로로 긴 장면(가로÷세로 1.25 미만)에서는 최대 2배까지 멀리서 본다 |
| 자동 회전 | 처음 들어왔을 때만 아주 느리게(한 바퀴 약 90초). 사용자가 한 번 조작하면 끄고 다시 켜지 않는다 |
| 인트로 | 없음. 첫 프레임부터 처음 시점이다 |
| 첫 프레임의 장면 시각 | 포스터를 찍은 장면 시각과 같은 값에서 시작한다. 포스터가 3D로 바뀔 때 화물선·전지판·지구·별 반짝임이 튀지 않는다 |
| 화면 비율 맞춤 | **카메라 위치는 폭 구간마다 하나로 고정한다.** 화면 비율이 달라 생기는 차이는 렌즈 배율(카메라 zoom)과 시야 이동(`setViewOffset`)으로만 맞춘다. 그래서 같은 폭 구간 안에서는 원근이 늘 같고, 포스터와 3D 첫 화면이 겹친다(`ski-mountain` 검수 4절 1번) |

### 4-1. 임시 토큰 — 어두운 UI 한 벌(DESIGN.md 확정 전까지)

| 움직임 | 마우스 올림 100ms · 표지 나타남 150ms, 숨김 100ms · 포스터→장면 교체 200ms · 명소로 시점 이동 600ms(감속 곡선, 10절 예외) · 돌리기·가까이·멀리 버튼 한 번 400ms · 낮 쪽·밤 쪽 전환 600ms |
| 색 체계 선언 | `<meta name="color-scheme" content="dark">` + CSS `color-scheme: dark`, `<meta name="theme-color" content="#0B1020">`(`CLR-DARK-10`). 이 화면에는 `<select>` 가 없다 |

- 정거장 이름도 `text.display` 28 로 둔다. 넓은 폭에서도 키우지 않는다. 이 화면의 주인공은 장면이다.

| 움직임 멈추기·다시 켜기 | 토글 버튼 | Tab + Enter·Space | 라벨이 다음 행동으로 바뀐다. 별·지구·전지판·화물선·자동 회전이 멈추거나 다시 움직인다 |
| 지구 밤 쪽으로·낮 쪽으로 가기 | 토글 버튼 | Tab + Enter·Space | 빛과 색이 600ms 에 바뀐다(움직임 줄이기·멈춤이면 즉시). 라벨이 다음 행동으로 바뀐다. 포커스는 버튼에 그대로 있다 |
| 이동 중 다른 입력 | 시점 이동 중에 끌기·휠·탭 | 이동 중에 다른 버튼 | 진행 중인 이동을 바로 취소하고 새 입력을 따른다 |

- 조작 안내는 입력 방법에 맞춰 세 가지 중 하나만 보인다. 넓은 폭 + 마우스: 휠 안내. 좁은·중간 폭 + 마우스: 버튼 안내. 터치: 두 손가락 안내.
- 포커스 순서: 건너뛰기 링크 → 움직임 토글 → 지구 쪽 토글 → 시점 조작 버튼 5개 → 명소 목록 → 상세 안 요소(있으면). 좁은 폭의 화면 순서(장면 → 목록)와 같다.
- 단축키: Esc 만 둔다. 보이는 툴팁이 있으면 툴팁을 닫고, 없으면 처음 시점으로 간다. 글자 한 개 단축키는 두지 않는다.
- 표지는 `aria-hidden="true"`, `tabindex="-1"` 로 둔다. 키보드와 화면낭독기는 목록으로 같은 일을 한다.
- 표지는 자동 회전 중에도 장면 토글 아래로 오래 숨지 않게 둔다. 명소가 모두 정거장 몸통 높이(위아래 약 3) 안에 있고, 처음 시점이 버튼 묶음을 뺀 빈 자리에 정거장을 맞추므로 표지는 버튼 띠와 겹치지 않는다. 태양 전지판 표지는 카메라에 가까운 쪽 날개에 붙어 화면 아래쪽에 머문다.
- 장면 `<canvas>` 에는 `role="img"` 와 7절의 대체 텍스트를 단다. 3D가 보이지 않는 loading·lost·fallback 에서는 캔버스에 `aria-hidden="true"` 를 주고, ready 에서는 포스터 쪽에 준다. 같은 이름의 그림이 접근성 트리에 두 번 나오지 않는다.
- 배너를 지우거나 바꿀 때 포커스가 배너 안에 있었으면, 장면 토글 가운데 보이는 첫 버튼으로 옮긴다. 보이는 토글이 없으면 명소 목록 머리(`#landmarks`, `tabindex="-1"`)로 옮긴다. 포커스가 body 로 떨어지지 않는다(`moveFocusAfterBanner()`).
- live 영역(배너 자리 `aria-live`, 진행 문구 `role="status"`)은 비어 있어도 렌더링해 두고 화면에서만 숨긴다. `display:none` 을 쓰지 않는다.

해당 없음 — 새 샘플이다. 바탕 샘플의 화면을 바꾸지 않는다. 바탕 샘플에서 가져온 동작(부팅 두 갈래·안전장치·포스터 배치·쿼리 파라미터·접근성 처리, 공통 결함 4건 수정)은 모두 유지한다.

## 10. 설계 메모 — 흔한 기본값과 비교

| 처음 안 | 흔한 기본값과 같은 점 | 바꾼 것 |
|---|---|---|
| 어두운 UI + 청록·보라 네온 테두리와 빛 번짐(HUD 느낌) | 우주 화면의 가장 흔한 모양이다. `SLOP-01`·정적 점검 S9 가 지목한 AI 기본 색·효과다 | 무채색에 가까운 어두운 남색 표면 단계 + 채도를 낮춘 호박색 강조 하나. 테두리는 옅은 흰빛 반투명, 빛 번짐 없음. 강조색은 정거장의 금빛 단열 띠와 같은 계열이라 장면과 UI 가 한 벌로 읽힌다 |
| 반투명 유리 패널(뒤 장면이 흐리게 비치는 패널) | 우주·3D 화면의 흔한 연출이다(정적 점검 S9). 움직이는 장면 위에서 글자 대비가 프레임마다 바뀐다 | 불투명 표면. 높이는 표면 밝기로 보인다 |

| 진입할 때 우주에서 정거장으로 날아드는 카메라 인트로 | 3D 첫 화면의 흔한 연출이다. 사용자가 기다려야 하고 어지럼을 줄 수 있다(`MOT-06`) | 인트로 없음. 첫 프레임부터 처음 시점. 아주 느린 자동 회전만 두고 첫 조작 때 끈다 |
| 별을 빠르게 깜빡이게 | 반짝이는 별은 흔한 장식이다. 빠른 깜빡임은 어지럼과 주의 분산을 부른다(`SLOP-11`) | 별마다 1.5~4초 주기로 밝기만 천천히 바뀐다. 움직임 멈춤·움직임 줄이기에서 멈춘다 |
| 명소마다 사진·아이콘이 붙은 카드 격자 | `SLOP-06`·`SLOP-07` 이 지목한 카드 키트다 | 이름 + 위치 한 마디의 목록 행. 좁은 폭은 칩 |

- `MOT-01` 예외: 시점 이동과 지구 쪽 전환은 600ms 로 한다. 바탕 샘플과 같은 이유다 — 큰 회전을 400ms 에 끝내면 너무 빨라 오히려 어지럽다(추정). 대신 감속 곡선을 쓰고(`MOT-04`), 입력이 오면 바로 취소하고(`MOT-10`), OS 움직임 줄이기가 켜지면 즉시 전환한다(`MOT-06`).
- 위키 공백: 이 위키의 화면 유형 표에는 소비자용 첫 화면·3D 화면 유형이 없다. 이 설계서는 목록 + 상세로 옮겨 적었다. 다크 페이지는 "테마 선택"만 다루고, 장면 때문에 어두운 UI 한 벌만 두는 경우는 다루지 않는다.
