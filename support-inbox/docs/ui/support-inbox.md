## 1. 사용자와 할 일

| 항목 | 내용 | 확인 / 가정 |
|---|---|---|
| 사용자 | 고객 상담 담당자(상담원). 웹 채팅·메일·앱으로 들어온 고객 대화에 답한다 | 확인 — 작업 지시 |
| 주요 작업 | ① 답할 대화를 고른다(열린 대화, 안 읽은 메시지) ② 메시지를 읽고 답한다(빠른 답변을 골라 쓰기도 한다) ③ 대화 상태를 바꾼다(대기·종료), 담당자 없는 대화를 맡는다 | 확인 — 작업 지시(①②), 가정(③) |
| 빈도 | 근무 시간 내내 열어 둔다. 하루 수십 건의 대화를 오간다 | 가정 |
| 들어오는 길 | 업무 시작 때 바로 연다. 알림이나 공유받은 주소(`?c=<대화 id>`)로 특정 대화를 연다 | 가정 |
| 나가는 길 | 이 화면에 머문다. 머리줄 "UI 샘플" 링크로 샘플 목록에 간다 | 확인 — 저장소 구조 |

## 2. 정보 우선순위

| 순위 | 정보·행동 | 이 순위인 이유 |
|---|---|---|
| 1 | 고른 대화의 메시지와 답장 입력창 | 상담원이 하는 일 대부분이 읽고 답하는 것이다(`PAT-CHAT-01`) |
| 2 | 답할 대화 목록 — 상태, 안 읽은 메시지 수, 마지막 메시지, 시각 | "무엇부터 답하나"를 고르는 근거다 |
| 3 | 고객 정보 — 이름·등급·연락처·이전 문의 3건 | 답을 쓸 때 맥락이 된다. 대화를 가리지 않게 옆에 둔다(`PAT-CHAT-03`) |
| 4 | 거르기 — 상태(열림·대기·종료), 담당자, 검색 | 목록이 길 때 범위를 줄인다 |
| 5 | 보내기 결과 — 보내는 중·보냄·보내지 못함 | 보낸 줄 알았는데 안 간 메시지를 막는다(`PAT-CHAT-04`·`PAT-CHAT-07`) |
| 6 | 화면 밝기, 샘플 목록 링크 | 화면 견본으로서의 보조 조작 |

- 주 행동: 답장 "보내기"(대화 영역). 목록 영역과 고객 정보 영역에는 강조색 채움 버튼을 두지 않는다(`PAT-ARC-02`·`CLR-07`).

## 3. 영역 구성

본문은 kit 의 앱 틀(`.ds-app`) 안에서 "목록 | 대화" 두 칸으로 나눈다. 두 칸으로 나눌지는 **본문 폭**으로 정한다(컨테이너 쿼리, 기준 40rem). rem 기준이라 글자를 200% 로 키우면 같은 창에서도 한 칸으로 바뀐다(`TYP-04`).

| 영역 | 위치 | 담는 것 | 컴포넌트 | 좁은 폭(375) | 중간 폭(768) | 넓은 폭(1280 이상) |
|---|---|---|---|---|---|---|
| 건너뛰기 링크 | 맨 앞 | "대화 목록으로 건너뛰기", "답장 쓰기로 건너뛰기" | `ds-skip-link` | 같음 | 같음 | 같음 |
| 머리줄 | 위, 붙음 | 메뉴 버튼, "UI 샘플" 링크, 화면 제목(h1 "상담 인박스"), "가상의 샘플 데이터입니다", 화면 밝기 | `ds-topbar` `ds-segmented` | 메뉴 버튼 보임. 데이터 안내는 둘째 줄. 밝기는 아이콘만(툴팁) | 메뉴 버튼 보임, 밝기 글자 보임 | 메뉴 버튼 숨김 |
| 옆 메뉴 | 왼쪽 | 담당자별 보기(모든 대화·내 대화·담당자 없음), 팀원 3명, 이 저장소 링크 2개. 보기마다 지금 상태 필터의 대화 수 | `ds-sidenav` `ds-nav__link` `ds-nav__count` | 서랍 | 서랍 | 왼쪽 240 에 붙음 |
| 배너 자리 | 본문 맨 위(두 칸 위에 걸침) | 목록 불러오기 실패, 연결 끊김, 먼저 맡은 대화 | `ds-banner-slot` | 같음 | 같음 | 같음 |
| 목록 칸 | 본문 왼쪽 | 지금 보기 이름과 건수, 상태 묶음 버튼(열림·대기·종료·전체 + 개수), 대화 찾기, 대화 목록 | `ds-segmented` `ds-search` 샘플 `si-row` | 대화를 고르지 않았을 때 전체 폭. 고르면 숨김 | 왼쪽 약 290 | 왼쪽 272~352(본문의 38%) |
| 대화 칸 | 본문 오른쪽 | 머리(뒤로·고객 이름·채널·담당자·상태 메뉴·내가 맡기·고객 정보 열기), 메시지 흐름, 답장 입력창 | `ds-btn` `ds-menu` `ds-badge` `ds-textarea` 샘플 `si-msg` | 대화를 고르면 전체 폭, "목록으로" 버튼 보임 | 오른쪽 나머지 | 가운데 나머지 |
| 고객 정보 패널 | 오른쪽 | 이름·등급, 연락처·메일·고객 번호·가입일, 이전 문의 최대 3건 | `ds-app__panel` `ds-panel` `ds-dl` `ds-badge`, 여닫기는 kit `DS.panel` | 버튼으로 열고 머리줄 아래를 전체 폭으로 덮음(뒤는 가림막 + inert) | 버튼으로 열고 오른쪽 360 으로 덮음(뒤는 가림막 + inert) | 오른쪽 360 에 붙음. 첫 방문이면 처음부터 열림. 버튼으로 접는다 |

- 앱 틀은 문서 전체 스크롤 대신 **칸마다 스크롤**한다. 답장 입력창을 늘 화면 아래에 두기 위해서다(10절 예외). 배너 자리는 칸 스크롤 영역 밖(본문 맨 위)에 둔다.
- 대화를 고르지 않은 채 두 칸 폭이면 목록 맨 위 대화를 연다. 주소에는 `?c=` 를 기록 없이 적는다.
- 고객 정보 패널 열림은 주소 `?info=open` 에 남는다(kit `DS.panel`, `data-url-key="info"`). 주소에 `c`·`info` 가 모두 없는 첫 방문이고 패널을 붙일 자리가 있으면 열어 둔다.
- 메시지 흐름의 맨 아래를 보고 있었으면, 배너가 떠서 칸 높이가 바뀌어도 맨 아래에 붙어 있는다.

## 5. 상태

| 상태 | 언제 | 보이는 것 | 문구 | 사용자 행동 | 확인 방법 |
|---|---|---|---|---|---|
| 초기 로딩 | 처음 열 때(0.25초 흉내 — 0.3초 안이라 표시하지 않음). `?state=loading` 이면 끝나지 않는다 | 0.3초 뒤 목록 칸에 행 모양 스켈레톤 6줄, 대화 칸에 말풍선 모양 스켈레톤. 목록 `aria-busy="true"` | live: "대화 목록을 불러오는 중이에요" | 없음 | `?state=loading` 스크린샷, `aria-busy` |
| 부분 로딩 | "다시 불러오기"·"다시 연결"을 눌렀을 때 | 그 버튼만 "불러오는 중…"·"연결하는 중…" + 회전 표시(0.3초 뒤) | 같음 | 기다린다 | 오류 상태에서 버튼을 눌러 `aria-busy` 확인 |
| 빈 화면(처음 사용) | 답할 대화가 하나도 없을 때(`?state=zero` — 열린 대화를 모두 종료로 바꾼 데이터) | 목록 칸 빈 상태: 아이콘, 제목, 설명, 종료한 대화 보기 | "지금 답할 대화가 없어요" / "새 대화가 오면 여기에 바로 보여요." / "종료한 대화 보기" | 버튼 | `?state=zero` 스크린샷 |
| 빈 화면(검색·필터 결과 없음) | 조건에 맞는 대화가 없을 때. `?state=empty` 는 상태 "대기" + 내 대화 + 검색어 "택배 분실"로 연다 | 목록 칸 빈 상태 + 켜 둔 조건을 지우는 버튼. 대화 칸은 "고른 대화가 없어요" | "조건에 맞는 대화가 없어요" / "검색어를 바꾸거나 필터를 끄면 더 많은 대화가 보여요." / "검색어 지우기" · "필터 모두 끄기" | 버튼 | `?state=empty` 스크린샷, live "대화 0건이 보여요" |
| 불러오기 오류 | 목록을 받지 못했을 때(`?state=error`) | 본문 맨 위 위험 배너(닫기 + "다시 불러오기"). 목록 칸은 비우고 대화 칸은 안내 | 배너: "대화 목록을 불러오지 못했어요" / "연결이 잠시 끊겼어요. 다시 불러오면 이어서 볼 수 있어요." 대화 칸: "고른 대화가 없어요" / "목록을 다시 불러오면 대화를 고를 수 있어요." | 다시 불러오기(두 번째는 성공, `DS.busy` 로 "불러오는 중…") · 닫기 | `?state=error` 스크린샷, `#ds-live-alert`, 다시 불러온 뒤 포커스가 첫 대화 행 |
| 저장·전송 오류 | 답장을 보내지 못했을 때(`?state=send-fail` — 첫 시도마다 실패. 대화 `c01` 에 실패한 말풍선 1개를 미리 둔다) | 말풍선은 그대로 두고 아래에 오류 아이콘 + 글 + "다시 보내기". 목록 행에도 "보내지 못했어요"(다른 대화를 보고 있어도 놓치지 않게) | "보내지 못했어요" / "다시 보내기". live(assertive): "메시지를 보내지 못했어요. 다시 보내기를 눌러 주세요." | 다시 보내기 → 보내는 중 → 보냄. 버튼이 사라지면 포커스는 답장 입력창 | `?state=send-fail` 스크린샷, 다시 보내기 뒤 포커스 |
| 권한 없음 | 해당 없음 — 이 샘플의 상담원은 모든 대화를 보고 답할 수 있다. 권한 관리 샘플이 따로 다룬다 | — | — | — | — |

## 6. 상호작용

| 동작 | 마우스·터치 | 키보드 | 결과 |
|---|---|---|---|
| 대화 열기 | 행 누르기 | 목록에서 ↑ ↓ Home End 로 옮기고 Enter | 주소에 `?c=` 를 기록과 함께 남긴다. 한 칸 폭이면 대화 칸으로 바뀌고 포커스는 대화 제목. 두 칸 폭이면 포커스는 행에 남는다 |
| 목록으로 돌아가기(한 칸 폭) | "목록으로" 버튼, 브라우저 뒤로 | Enter, Alt+← | 목록 칸으로 바뀌고 포커스는 보던 행 |
| 상태 거르기 | 묶음 버튼 | ← → Home End | 목록이 바뀌고 개수 알림, 주소 `?status=` |
| 담당자 거르기 | 옆 메뉴 보기 링크 | Tab · Enter | 목록이 바뀌고 지금 보기에 `aria-current`, 주소 `?who=` |
| 검색 | 대화 찾기 입력 | 글 입력(0.25초 뒤 거름), Esc 로 지움 | 이름·회사·메시지에서 찾는다. 주소 `?q=` |
| 답장 쓰기 | 입력창 | Ctrl+Enter(맥은 ⌘+Enter)로 보내기, Enter 는 줄바꿈 | 말풍선이 바로 붙고 "보내는 중…" → "보냄" |
| 빠른 답변 | "빠른 답변" 메뉴 | ↓ ↑ Enter Esc | 고른 글을 입력창 끝에 붙이고 포커스는 입력창 |
| 다시 보내기 | 버튼 | Enter | 같은 말풍선이 "보내는 중…"이 된다. 포커스는 입력창 |
| 상태 바꾸기 | "상태" 메뉴 | ↓ ↑ Enter Esc | 배지·행·시스템 메시지가 바뀐다. 목록에서는 다음에 거를 때 빠진다(지금 연 대화가 갑자기 사라지지 않게) |
| 내가 맡기 | 버튼(담당자 없는 대화만) | Enter | 담당자가 "나"가 되고 시스템 메시지. 버튼이 사라지면 포커스는 상태 메뉴 버튼 |
| 고객 정보 열고 닫기 | "고객 정보" 버튼(`data-ds-panel`), 패널 닫기(`data-ds-panel-close`), 가림막 | Enter, 패널 안 Esc | kit `DS.panel`. 열면 포커스는 패널 제목, 닫으면 연 버튼으로. 1280 이상은 붙고, 그보다 좁거나 글자를 키워 자리가 모자라면 덮는다(뒤는 가림막 + inert). 주소 `?info=open` |
| 옆 메뉴 서랍 | 메뉴 버튼 | Enter, Esc | kit 동작 그대로 |

- 포커스 순서: 건너뛰기 링크 → 머리줄 → 옆 메뉴 → 배너 → 목록 칸(필터 → 찾기 → 목록) → 대화 칸(머리 → 메시지 → 입력창) → 고객 정보 패널.

- 새 메시지가 와도 포커스를 옮기지 않고, 목록 행을 다시 그리지 않는다(바뀐 행만 고친다).

## 10. 설계 메모 — 흔한 기본값과 비교

| 처음 안 | 흔한 기본값과 같은 점 | 바꾼 것 |
|---|---|---|
| 내 말풍선을 강조색 파랑으로 채우기 | 메신저를 흉내 낸 파란 말풍선. 강조색이 화면 절반을 덮는다(`CLR-07`) | 고객은 옅은 회색 바탕, 상담원은 흰 바탕 + 테두리. 오른쪽 정렬과 보낸 사람 이름으로 나눈다. 강조색은 "보내기"에만 |
| 행마다 둥근 얼굴 그림 + 색 점으로 안 읽음 표시 | 장식 아바타, 색만으로 상태(`STA-13`) | 얼굴 그림을 빼 폭을 아낀다. 안 읽음은 굵은 이름 + 숫자 배지 + 화면낭독기 글 "안 읽은 메시지 2건" |
| 행을 카드 상자로 늘어놓기 | 모든 것을 테두리 상자로 감싼 목록(`CMP-LIST-13`) | 행 사이 옅은 구분선만 |
| 고객 정보를 버튼으로 여는 모달 | 대화를 덮는 모달(`PAT-CHAT-03`) | 1280 이상은 붙은 패널, 그보다 좁으면 대화 위에 덮는 비모달 패널 |
| 전송 실패를 토스트로 | 3초 뒤 사라지는 알림(`PAT-CHAT-07`) | 실패한 말풍선이 남고 그 자리에 "다시 보내기" |
| Enter 로 보내기 | 여러 줄 답장을 쓰다 실수로 보냄 | Ctrl/⌘+Enter. 안내는 키보드가 있는 화면에서만 |
| 새 메시지가 오면 목록을 다시 정렬 | 보던 행이 움직이고 포커스가 사라진다 | 바뀐 행만 고치고 자리는 그대로. 다음에 거를 때 다시 정렬 |
| 담당자 필터를 고르기 상자로 | 목록 칸 위에 필터가 쌓여 목록이 짧아진다 | 담당자별 보기를 옆 메뉴에 둔다(옆 메뉴가 실제로 하는 일이 생긴다). 지금 보기 이름은 목록 칸 머리에 남긴다 |

### 예외

| 예외 | 이유 |
|---|---|
| 문서 전체 스크롤 대신 칸마다 스크롤(DESIGN.md Layout 은 문서 스크롤) | 답장 입력창과 대화 머리를 늘 보이게 하는 대화 화면의 기본 구조다. 배너 자리는 칸 밖(본문 맨 위)에 둬서 "스크롤 영역 안 배너 금지"를 지킨다 |
| 샘플 토큰 3개(`--support-inbox-*`) | kit 에 칸 폭·말풍선 폭·입력창 최대 높이 토큰이 없다 |
| 두 칸 기준을 컨테이너 쿼리 40rem 으로 | kit 의 폭 경계(px 미디어 쿼리)는 글자 크기를 따르지 않는다. 본문 폭을 rem 으로 재야 글자 200% 에서 칸이 좁아지지 않는다 |
| 고객 정보 패널은 창이 1280 이상이고 창 폭이 72rem 이상일 때만 붙인다. 그 밖에는 덮는다 | kit `DS.panel` 은 1280px 이상이면 늘 붙인다. 글자 200% 에서 패널(42vw)까지 붙으면 본문이 262px 만 남는다. 샘플 `fixDock()` 이 붙이지 않고 덮는 패널로 바꾼다(가림막 + 뒤 inert). 임시 메움이라 kit 에 요청했다 |
| 개수(옆 메뉴·상태 묶음 버튼)는 검색어까지 반영한다 | 검색 결과가 0건인데 "대기 1"이 남으면 헷갈린다. 개수는 그 보기·상태를 누르면 보일 건수다 |
