- 실존 장소·실제 사찰을 본뜨지 않은 가상의 장소다. 종교 의식이나 특정 종단을 다루지 않는다. 건축과 풍경으로만 보여 준다.

## 1. 사용자와 할 일

| 항목 | 내용 | 확인 / 가정 |
|---|---|---|
| 사용자 | 이 산사 마을에 관심이 있는 일반 방문자 | 가정 — 요청에 사용자 설명이 없다 |
| 주요 작업 | ① 절과 마을 전체 모습을 본다 ② 명소 하나를 골라 위치와 설명을 본다 ③ 봄·여름·가을·겨울 모습을 견줘 본다 | 요청("산속 오래된 절과 그 아래 작은 마을", "봄 · 여름 · 가을 · 겨울 4단계")에서 정함 |
| 빈도 | 방문 한 번에 몇 분, 명소 2~5곳과 계절 2~4개를 본다 | 가정 |
| 기기 | 휴대폰 방문이 많다. 그래서 성능 예산은 휴대폰 기준으로 잡는다 | 가정 |
| 들어오는 길 | 링크·검색으로 사이트 첫 화면에 들어온다 | 가정 |
| 나가는 길 | 없음 — 이번에는 첫 화면 1장이고 바깥 링크를 두지 않는다 | 열린 질문 5번 기본안 |

## 2. 정보 우선순위

| 순위 | 정보·행동 | 이 순위인 이유 |
|---|---|---|
| 1 | 산 중턱의 절과 그 아래 마을이라는 전체 모습(3D 장면) | 방문자의 첫 판단은 "여기는 어떤 곳인가"다. 장면이 그 답이다 |
| 2 | 명소 5곳의 이름과 위치 | 장면을 본 다음 "무엇이 있나"를 찾는다. 표지와 목록이 같은 정보를 준다 |
| 3 | 계절 고르기(봄·여름·가을·겨울) | 이 화면만의 볼거리다. 지금 어느 계절인지 늘 보여야 한다 |
| 4 | 고른 명소의 설명 | 관심 가는 곳을 고른 뒤에 필요하다 |
| 5 | 둘러보는 방법(끌기·확대·버튼) | 처음 한 번 필요하다. 강제 튜토리얼 대신 맥락 안내로 준다 |
| 6 | 움직임 멈추기 | 대부분은 안 쓰지만, 어지럼을 느끼는 사람에게는 꼭 필요하다. 꽃잎·낙엽·눈이 계속 떨어지는 화면이라 더 중요하다. 항상 같은 자리에 둔다 |

- 주 행동(primary action): 명소 고르기.
- 계절 고르기는 보조 행동이다. 다만 늘 보이고, 지금 계절이 채워진 칸으로 드러난다.

- 가로 휴대폰(높이 480 미만, 가로가 더 김): 장면은 왼쪽 60% 를 높이 전체로 채운다. 오른쪽 40% 에 목록과 상세를 두고 그 열만 스크롤한다.
- 넓은 폭에서 휠은 확대에 쓴다(페이지가 스크롤되지 않는다). 좁은·중간 폭에서는 휠을 페이지 스크롤에 두고, 확대는 버튼과 두 손가락 집기로만 한다. 조작 안내 문구도 이 조건에 맞춰 고른다(7절).
- 장면 위에 얹는 글자는 모두 불투명 표면 위에 둔다. 움직이는 장면 위 글자는 프레임마다 대비가 바뀌기 때문이다. 꽃잎·낙엽·눈은 3D 장면 안에서만 그리고 UI 위로 떨어지지 않는다.

### 3-1. 장면 구성

모양은 저폴리(면이 보이는 단순한 입체)와 납작한 음영으로 만든다. 장난감 모형처럼 보이게 한다. 모델·텍스처 파일은 쓰지 않고 모두 코드로 만든다. 실제 사찰·마을의 배치·건물을 본뜨지 않는다. 가상의 장소다.

| 요소 | 위치 | 움직임 | 표지 |
|---|---|---|---|
| 산(지형) | 북쪽에 꼭대기가 둥근 큰 산, 동서 봉우리, 절을 감싸는 낮은 능선, 마을 둘레 낮은 언덕. 높이 함수로 평면 격자(`PlaneGeometry`)의 꼭짓점을 올린다. 절 자리는 계단식 단 2개(앞마당 단, 본당 단)로 평평하게 다진다. 지형 끝은 골짜기 바닥과 같은 높이·색으로 녹인다 | 없음 | 없음 |
| 지형 색 | 삼각형마다 한 색. 풀밭·숲 바닥·바위·흙길과 마당·논밭·골짜기로 나눈다. 계절마다 색이 바뀐다(4-1절) | 계절 전환 | 없음 |
| 골짜기 바닥 · 뒤쪽 산줄기 · 먼 산 | 마을 둘레 평지, 절 뒤(북쪽) 부채꼴로 겹겹이 선 산줄기, 둘레 먼 산. 산줄기와 먼 산은 빛을 받지 않는 단색 실루엣이고 안개가 계절 하늘색으로 덮는다 | 없음 | 없음 |
| 본당 | 절 맨 위 단 한가운데. 높은 돌 단 위에 기둥·벽·넓은 기와지붕(처마 끝이 살짝 들린 모임지붕) | 없음 | 본당. 처음 시점의 회전 중심 바로 위라 자동으로 둘러볼 때도 화면에서 자리가 움직이지 않는다 |
| 석탑 | 앞마당, 본당 앞 왼쪽 | 없음 | 석탑 |
| 종각 | 앞마당 동쪽 끝 작은 둔덕. 기둥 4개 + 모임지붕 + 매단 종 | 없음 | 종각 |
| 산문 | 앞마당 아래 돌계단이 시작하는 곳. 기둥 4개 + 기와지붕 | 없음 | 산문 |
| 연못과 돌다리 | 마을 어귀, 마을에서 산문으로 가는 흙길 위. 타원 연못 + 둥글게 휜 돌다리 | 물결이 번진다. 겨울에는 얼어서 물결이 없다 | 연못과 돌다리 |
| 마을 | 산 아래 평지. 낮은 집 열여섯 채(흰 벽 + 기와지붕 또는 초가지붕), 동쪽에 논밭 | 집 네 채의 굴뚝에서 연기가 천천히 오른다 | 없음 |
| 돌 축대 · 돌계단 | 두 단의 앞면과 산문에서 앞마당까지 | 없음 | 없음 |
| 나무 | 활엽수(둥근 잎 덩어리 + 줄기, 계절마다 색이 바뀐다)와 소나무(사철 푸른 뾰족나무, 겨울에 꼭대기에 눈) | 계절 전환 | 없음 |
| 새 | 종각 위 하늘을 천천히 도는 새 다섯 마리 | 날갯짓하며 돈다 | 없음 |
| 계절 입자 | 절과 마을 둘레 공간 | 봄 꽃잎, 가을 낙엽, 겨울 눈이 천천히 떨어진다. 여름은 입자 없음 | 없음 |

계절은 같은 장면에 빛·색·안개·입자·잎 모양만 바꾼다. 건물 모양과 명소 위치는 같다.

| 항목 | 봄 | 여름 | 가을(기본) | 겨울 |
|---|---|---|---|---|
| 하늘·안개 | 옅은 봄 하늘(뿌연 하늘색) | 맑고 짙은 하늘색. 안개가 멀다 | 맑은 가을 하늘 | 흐린 회청색. 안개가 가까워 먼 산이 흐려진다. 명소는 또렷하게 남긴다 |
| 주 빛 | 부드러운 해 | 강한 해, 그림자가 또렷하다 | 따뜻한 낮은 해 | 흐린 날 빛. 하늘빛을 키워 면 사이 명암 차가 줄어든다 |
| 땅 | 연두 풀밭, 물 댄 논 | 짙은 초록 풀밭, 푸른 논 | 마른 황토빛 풀밭, 누런 논 | 눈 덮인 땅 |
| 활엽수 잎 | 연분홍 꽃 + 연두 잎이 섞인다 | 짙은 초록. 잎 덩어리가 조금 커진다(짙은 녹음) | 빨강·주황·노랑 단풍 | 잎이 진다(잎 덩어리를 작고 옅은 회갈색으로) |
| 지붕 | 기와(짙은 회색)·초가(볏짚색) | 같음 | 같음 | 눈 덮인 흰색 |
| 연못 | 물빛 | 짙은 물빛 + 연잎 | 물빛 | 얼음(물결 없음) |
| 입자 | 꽃잎. 높은 품질 1,400개, 낮은 품질 500개 | 없음 | 낙엽. 높은 품질 800개, 낮은 품질 300개 | 눈. 높은 품질 2,400개, 낮은 품질 900개 |
| 표지·패널 | 흰 표면 | 같음 | 같음 | 같음(UI 는 계절과 상관없다) |

- 들어올 때는 가을로 시작한다(열린 질문 4번 기본안). `?season=` 이 있으면 그 계절로 시작한다.
- 고른 계절은 주소에 `?season=<id>` 로 남긴다. 가을이면 지운다(`history.replaceState`). 새로고침·공유해도 같은 계절이 열린다.
- 계절 전환은 빛·색·안개·잎 색·잎 크기·지붕 색·입자 투명도를 600ms 에 바꾼다(감속 곡선, 토큰 `motion.season-shift`). 바뀌는 중에 다른 계절을 고르면 지금 섞인 상태에서 새 계절로 이어 바꾼다. OS 움직임 줄이기가 켜져 있거나 움직임 멈춤이면 즉시 바꾼다.
- 움직임을 멈추면 입자도 그 자리에 멈춘다. 입자는 보이되 떨어지지 않는다.
- 품질이 낮으면 입자 수를 줄인다(위 표).

### 3-2. 시점(카메라)

| 항목 | 값 |
|---|---|
| 처음 시점 | 남남동쪽 위에서 비스듬히 내려본다(내려보는 각 21°, 회전 중심 = 본당 위, 거리 100). 마을과 연못이 앞, 절이 가운데, 산과 하늘이 시선 끝. 카메라 자리는 모든 화면 크기에서 같다. 화면 크기에 맞추는 일은 시야 배율(`camera.zoom`)과 시야 이동(`setViewOffset`)으로만 한다. 명소·마을 묶음은 맞춤 영역의 62% 를 차지한다(좁은 장면에서는 장면 높이의 45% 까지, 맞춤 영역의 92% 안에서 키운다). 남는 자리로 뒷산·하늘·마을이 보인다 |
| 맞춤 영역 | 장면에서 장면 토글 묶음의 실제 아래 끝 + 표지 높이(누르는 영역 높이의 0.8 — 알약 윗변까지. 글자 200% 면 같이 커진다)부터 시점 버튼 묶음의 실제 위 끝까지, 넓은 폭에서는 정보 패널 오른쪽. 명소 5곳의 표지 자리와 바닥, 마을 끝이 이 영역 안에 들어오게 배율을 정하고 가운데를 맞춘다. 버튼 묶음의 높이는 그때그때 재므로 글자를 키우거나 버튼이 두 줄이 돼도 명소가 버튼에 깔리지 않는다 |
| 각도 제한 | 내려보는 각 12°~65°. 지평선 아래와 지형 바깥 끝이 보이지 않게 한다 |
| 거리 제한 | 가장 가까이: 가장 큰 명소(본당)가 장면 높이의 절반. 가장 멀리: 처음 거리의 1.6배 |
| 중심점 제한 | 사용자가 중심점을 옮기는 조작이 없다. 중심점은 처음 시점과 명소 시점 사이에서만 움직인다 |
| 명소를 고르면 | 중심점을 그 명소로, 거리를 명소 크기에 맞춰 옮긴다. 시야 이동도 함께 옮겨 고른 명소가 맞춤 영역 가운데에 온다. 거리 제한 안에서만 움직인다 |
| 자동으로 둘러보기 | 처음 들어왔을 때만 좌우로 천천히 흔든다(처음 방향에서 ±18°, 한 번 오가는 데 약 60초). 한 바퀴 돌리지 않는다 — 절이 산을 등지고 있어 뒤쪽에서는 산에 가려진다. 회전 중심이 본당이라 본당 표지는 그 자리에 머문다. 사용자가 한 번 조작하면 끄고 다시 켜지 않는다 |
| 인트로 | 없음. 첫 프레임부터 처음 시점이다 |
| 첫 프레임 | 포스터를 찍은 장면 시각과 같은 시각에서 시작한다. 포스터에서 실시간 장면으로 바뀔 때 입자·새·연기·물결 자리가 튀지 않는다 |

- 사용자가 직접 돌릴 때는 한 바퀴를 다 돌 수 있다(바탕 샘플과 같은 조작). 산 뒤쪽에서 가려진 표지는 숨긴다.

### 4-2. 기술 선택과 예산

| 항목 | 정한 것 | 이유 |
|---|---|---|
| 3D 라이브러리 | Three.js 0.187.0(MIT). 앱 코드가 쓰는 클래스만 한 파일로 묶어 `vendor/three/` 에 둔다(공용 뼈대의 `shared/scene3d/tools/build-three.mjs`) | CDN 장애와 외부 요청을 없앤다 |
| 모듈 불러오기 | importmap + ES 모듈. 빌드 도구 없음 | 정적 파일만으로 동작한다 |
| 실행 조건 | 서버(http·https)와 파일 더블클릭(`file://`) 모두. 바탕 샘플과 같은 두 갈래 부팅과 6초 안전장치 | 열린 질문 1번 |
| 그래픽 요구 | WebGL2 | Three.js 0.187 은 WebGL1 을 지원하지 않는다 |
| 지형 | `PlaneGeometry` 를 높이 함수로 변위하고, 삼각형마다 한 색. 삼각형마다 종류(풀밭·숲·바위·길·논밭·골짜기)를 정해 두고, 계절을 바꿀 때는 종류별 색만 바꿔 다시 칠한다. 지형은 그림자를 받기만 한다 | 계절마다 지형을 다시 만들지 않는다 |
| 나무 | 활엽수·소나무를 `InstancedMesh` 로 그린다. 잎 색은 인스턴스 색(`setColorAt`), 잎 크기는 인스턴스 행렬로 바꾼다 | 나무 수백 그루를 그리기 몇 번으로 |
| 계절 입자 | 꽃잎·낙엽·눈을 `Points` 3개로 그린다(종류마다 그리기 1번). 코드로 그린 작은 텍스처(32×32). 위치는 장면 시각 t 의 함수라 같은 t 면 늘 같은 자리다. 바뀌는 중에는 두 종류가 겹쳐 사라지고 나타난다 | 포스터와 첫 프레임이 맞는다 |
| 표지 가림 | 카메라에서 표지까지 높이 함수를 따라가며 산등성이가 가리는지 본다 | 지형 삼각형을 일일이 검사하지 않는다 |
| 모델·텍스처 | 없음. 모두 코드로 만든다 | 용량과 라이선스 문제를 없앤다 |
| 전송량 예산 | 압축 전송 기준 첫 방문 합계 300KB 이하 | 목표값(가정). 휴대폰 첫 방문 기준 |
| 삼각형 수 | 장면 전체 5만 개 이하(그림자 패스 포함) | 목표값(가정) |
| 해상도 상한 | `devicePixelRatio` 넓은 폭 2, 좁은·중간 폭 1.5 | 휴대폰 발열·배터리 |
| 높은 품질 | 넓은 폭 기본. 실시간 그림자 1개(해). 지형 격자 촘촘, 입자 많이 | — |
| 낮은 품질 | 좁은·중간 폭 기본, 또는 성능이 낮을 때 자동 전환. 실시간 그림자 대신 건물 아래 어두운 원판, 지형 격자 성기게, 입자 줄임 | 5절 "성능 낮음" |
| 포스터 | 계절 4개 × 폭 3개 = 12장(WebP). 크기는 넓은 폭 1430×858, 중간 폭 1134×804, 좁은 폭 740×1210. 첫 방문에는 지금 계절·지금 폭의 1장만 받는다(`<picture>`). 3D 첫 프레임과 같은 카메라 자리·거리에서, 그 폭의 기본 품질(넓은 폭 높은 품질, 좁은·중간 폭 낮은 품질)로, 같은 장면 시각에 찍는다. 화면 비율 차이는 시야 배율과 시야 이동으로만 맞춘다. 화면에서는 `js/framing.js` 가 3D와 같은 식으로 자리를 계산한다. 그 폭의 흔한 화면 크기를 덮고, 그보다 크거나 아주 납작한 창(예: 1366×600, 320 폭 글자 200%)은 가득 채우기로 둔다 — 전송량 예산 때문이다 | 교체 때 장면이 움직이지 않는다(`STA-03`) |
| 점광원 | 쓰지 않는다. 빛 번짐 후처리(bloom)도 쓰지 않는다 | 휴대폰에서 가장 비싸다 |
| 그리기 멈춤 | 탭이 숨겨지거나, 장면이 화면 밖이거나, 움직임 멈춤일 때 매 프레임 그리기를 멈춘다. 조작할 때만 그린다 | 배터리 |
| 터치 처리 | 좁은·중간 폭의 장면에 `touch-action: pan-y`. 한 손가락 가로 끌기는 회전, 세로 끌기는 페이지 스크롤 | 장면을 만져도 페이지가 내려가야 한다 |
| 기기 방향 센서 | 쓰지 않는다 | 진입하자마자 권한을 묻지 않는다 |
| 안전 영역 | `viewport-fit=cover` 를 쓰지 않는다 | `LAY-06` |
| 상태 주소 | 명소를 고르면 `?select=<id>`, 계절을 고르면 `?season=<id>`(가을이면 지움)를 주소에 남긴다(`history.replaceState`) | `PLT-WEB-10` |
| 자바스크립트 꺼짐 | 포스터 이미지 + 명소 5곳의 설명을 모두 펼쳐 보인다 | 설명은 HTML 에 미리 넣는다 |

| 이동 중 다른 입력 | 시점 이동 중에 끌기·휠·탭 | 이동 중에 다른 버튼 | 진행 중인 이동을 바로 취소하고 새 입력을 따른다 |

- 포커스 순서: 건너뛰기 링크 → 움직임 토글 → 계절 묶음(고른 칸 하나) → 시점 버튼 5개 → 명소 목록 → 상세 안 요소(있으면). 건너뛰기 링크는 바로 명소 목록으로 간다.
- 단축키: Esc 만 둔다. 보이는 툴팁이 있으면 툴팁을 닫고, 없으면 처음 시점으로 간다. 한 글자 단축키는 두지 않는다. 계절 칸에 포커스가 있을 때 화살표는 계절을 바꾸고 장면을 움직이지 않는다.
- 표지는 `aria-hidden="true"`, `tabindex="-1"` 로 둔다. 키보드와 화면낭독기는 목록으로 같은 일을 한다.
- 장면 `<canvas>` 에는 `role="img"` 와 7절의 대체 텍스트를 단다. 계절이 바뀌면 대체 텍스트도 바뀐다. 3D가 보이지 않는 loading·lost·fallback 에서는 캔버스에 `aria-hidden="true"` 를 주고, ready 에서는 포스터 쪽에 준다. 같은 이름의 그림이 접근성 트리에 두 번 나오지 않는다.
- 배너를 지우거나 바꿀 때 포커스가 배너 안에 있었으면, 장면 토글 가운데 보이는 첫 컨트롤(움직임 토글, 숨겨졌으면 고른 계절 칸)로 옮긴다. 그런 컨트롤이 없으면 명소 목록 머리(`#landmarks`, `tabindex="-1"`)로 옮긴다. 포커스가 body 로 떨어지지 않는다.
- live 영역(배너 자리 `aria-live`, 진행 문구 `role="status"`)은 비어 있어도 렌더링해 두고 화면에서만 숨긴다. `display:none` 을 쓰지 않는다.

## 10. 설계 메모 — 흔한 기본값과 비교

| 처음 안 | 흔한 기본값과 같은 점 | 바꾼 것 |
|---|---|---|
| 계절 탭 4개를 화면 위쪽에 큰 글자로 | 계절·날씨 샘플의 흔한 기본값이다. 탭은 다른 내용으로 가는 길로 읽히고, 장면 위를 넓게 가린다 | 장면 오른쪽 위에 작은 묶음 버튼(라디오) 하나. 바탕 샘플의 토글 자리와 같다 |
| 계절마다 화면 UI 색까지 바꾸기(봄 분홍, 가을 주황 …) | 테마 색을 계절에 맞추는 흔한 연출이다. 대비를 계절마다 다시 따져야 하고 강조색이 흔들린다 | UI 는 계절과 상관없이 흰 표면 + 단청 붉은색 하나. 계절은 장면 안에서만 바뀐다 |
| 화면 전체를 덮는 꽃잎·낙엽 오버레이(DOM·CSS) | 글자와 버튼 위로 입자가 지나가 읽기를 방해한다 | 입자는 3D 장면 안에서만 그린다. 산 안쪽 입자는 깊이로 가려진다. "움직임 멈추기" 하나로 함께 멈춘다 |
| 처음 들어오면 한 바퀴 계속 도는 자동 회전 | 3D 첫 화면의 흔한 기본값이다. 산을 등진 절은 뒤쪽에서 산에 가려지고, 표지가 토글 아래로 오래 숨는다(앞선 3D 샘플 검수 지적) | 좌우로 ±18° 만 천천히 흔든다. 회전 중심을 본당에 두어 가장 높은 명소의 표지가 움직이지 않는다 |
| 하늘 그라데이션(봄 새벽빛·가을 노을) | 장식 그라데이션 배경과 구분이 어렵다(`SLOP-03`) | 하늘은 단색 + 같은 색 안개 |
| 명소마다 아이콘 타일이 붙은 카드 격자 | `SLOP-06`·`SLOP-07` 이 지목한 카드 키트다 | 이름 + 위치 한 마디의 목록 행. 좁은 폭은 칩 |
| 3D를 불러오는 동안 가운데 스피너 | 기다림을 보이는 흔한 방법이다(`STA-14`) | 첫 프레임과 같은 포스터를 먼저 보인다 |
| 크림 바탕 패널 + 붉은 강조(옛 건물 느낌) | 크림·테라코타 조합 신호(`SLOP-02`)다 | 패널은 흰색, 옅은 바탕은 차가운 회색. 붉은색은 강조 하나에만 |

앞선 검수(`ski-mountain`·`city-night`)에서 남은 지적 가운데 처음부터 반영한 것:

| 지적 | 이 설계에서 |
|---|---|
| 포스터를 뒤로 물린 카메라로 찍어 교체 때 앞쪽이 20~30px 어긋난다 | 카메라 자리를 화면 크기와 상관없이 하나로 둔다. 화면 크기 맞춤은 시야 배율과 시야 이동으로만 한다. 그래서 포스터는 3D 첫 프레임을 늘리고 옮긴 그림과 같다(3-2절, 4-2절) |
| 포스터 모드가 늘 높은 품질로 그려 좁은·중간 폭의 첫 프레임(낮은 품질)과 다르다 | 포스터를 그 폭의 기본 품질로 찍는다(4-2절) |
| 포스터와 첫 프레임의 움직이는 물체 자리가 다르다 | 입자·새·연기·물결·자동으로 둘러보기를 전부 장면 시각의 함수로 만들고, 같은 시각에서 시작한다(3-2절 "첫 프레임") |
| "가까이 보기"를 거듭 누르면 명소 일부만 보인다 | 가장 큰 명소(본당)가 장면 높이의 절반이 되는 거리를 최소 거리로 둔다(3-2절) |
| 글자 200% 에서 두 줄이 된 토글이 첫 프레임의 명소를 가린다 | 맞춤 영역에서 토글·시점 버튼 묶음의 실제 높이를 뺀다(3-2절 "맞춤 영역") |
| 자동 회전 중 가장 높은 명소의 표지가 장면 토글 아래로 오래 숨는다 | 본당을 회전 중심에 두고, 한 바퀴 대신 ±18° 만 흔든다 |
| 공통 뼈대 4건(로딩 중 조작 안내 숨김, 배너 뒤 포커스 이동, live 영역 늘 렌더링, 멈춤 때 대체 텍스트 하나) | 바탕 샘플에서 고친 코드를 그대로 쓴다(5절, 6절) |

- `MOT-01` 예외: 시점 이동과 계절 전환은 600ms 로 한다. `MOT-01` 은 UI 전환을 400ms 이하로 정한다. 장면 전체의 색과 빛이 바뀌는 전환을 400ms 에 끝내면 번쩍이는 느낌이 든다(추정 — 실제 기기에서 확인). 대신 감속 곡선을 쓰고(`MOT-04`), OS 움직임 줄이기나 움직임 멈춤이면 즉시 전환한다(`MOT-06`).
- 위키 공백: 이 위키의 화면 유형 표에는 소비자용 첫 화면·3D 화면 유형이 없다. 이 설계서는 목록 + 상세로 옮겨 적었다. 라디오 묶음의 화살표 키 동작도 위키에 규칙이 없어 네이티브 라디오 동작을 따랐다.
